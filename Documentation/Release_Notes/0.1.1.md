# 0.1.1 — 2026-07-31

Documentation fix. **No library change from 0.1.0** — the compiled artefact is
identical in behaviour, and there is no reason to upgrade except for the
crates.io pages.

## Fixed

**Per-crate README taglines had every acronym lowercased.** The 0.1.0 READMEs
were generated by a script that ran Python's `str.capitalize()` over each
tagline. That uppercases the first character and lowercases *everything after
it*, which silently destroyed three of six:

| crate | 0.1.0 shipped | should have been |
|---|---|---|
| `ucal-core` | `... UCIDs ...` → `... ucids ...` | `UCIDs` |
| `ucal-civil` | `The si bridge: tt pivot, tai, utc, ... gregorian and julian` | `The SI bridge: TT pivot, TAI, UTC, ... Gregorian and Julian` |
| `ucal-cosmo` | `Flat lambdacdm, t <-> z, ...` | `Flat ΛCDM, t ↔ z, ...` |

Taglines are now written out rather than derived, so no transform can reach
them again.

Worth recording because of how the fault presented: it looked like crates.io
was normalising the text, and was diagnosed that way at first. It was ours, one
function call, in a generator nobody would think to check. Generated prose gets
the same scrutiny as generated code, or it ships wrong and reads plausible.

## Internal

Internal dependency requirements moved to `0.1.1` alongside the workspace
version. Leaving them at `0.1.0` would still have resolved — semver treats
`0.1.1` as compatible — but it would have permitted `ucal 0.1.1` to build
against `ucal-core 0.1.0`, which is not what a lockstep workspace release
means.

## Verification

376 tests green on both backends, `-D warnings` clean, lints and generated docs
current, `xtask` harness 96/96, `ucal-core` still builds `no_std` with no
allocator for `wasm32-unknown-unknown`. All six crates packaged and published.
