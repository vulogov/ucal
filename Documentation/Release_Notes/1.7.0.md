# 1.7.0 — 2026-08-22

Does each check catch what it exists for?

1.6.0 proved that every check in this repository **reads its subject**. This one
asks the harder question — whether reading it would produce a `FAIL` if the
subject were wrong — and answers it with a mechanism rather than a habit.

Twenty-one recorded mutations, one per check and one per distinct path where a
check has two, run against a sandbox copy of the tree. **One survived**, and it
was worth the cycle: the citation check had never read a word of the
documentation.

## The goal of this cycle: does each check catch what it exists for?

1.6.0 audited every check in this repository and asked one question of each:
**can it report success having examined nothing?** Fourteen could. All fourteen
are fixed, and the audit closed with a paragraph naming what it had not done:

> Whether a check is *correct* — whether it would catch the defect it exists for
> — is not answerable by pointing it at an empty directory. That needs a defect
> injected per check, which this project has done ad hoc and never
> systematically. Six were verified strict this way during 1.5.0. Fifteen have
> not been.
>
> That is not V2's job and it should not be smuggled into it. It is the next
> question, and it is a larger one.

This is that question.

A check now provably reads its subject. Nothing shows that reading it would
produce a `FAIL` if the subject were wrong. Those are different properties and
only the first has a mechanism.

### Why this is worth a cycle rather than an afternoon

Six checks were verified strict by hand in 1.5.0 and 1.6.0 — inject the defect,
watch it fire, revert. It works, it is convincing, and it is a **procedure**:
done when someone remembers, on the check they happen to be editing, and never
recorded afterwards. The evidence evaporates the moment the terminal closes.

The same argument this project has made about every other claim applies to its
own verification habits. A procedure is not a mechanism.

### Scope

**X1 — a defect corpus.** For each check, one recorded mutation that it must
reject: a citation pointed at a section that does not exist, a delta left
unapplied, a float in a shipped crate, a `Code` variant with no raiser, a
`#[non_exhaustive]` dropped, a manual page missing a field the program emits.
Each is a small, reversible edit with a known-correct verdict.

**Stop if** a mutation cannot be expressed as a reversible edit to a file — some
checks may need the tree to be in a state a patch cannot describe. Then that
check is listed as hand-verified with the date and the person, which is worth
less and is honest.

**X2 — run the corpus, and report what survives.** *(X1 has run it once: 20
mutations, 19 caught, 1 survivor. X2 fixes the survivor and wires the corpus into
CI, which X1 deliberately did not do — a known-red job in CI is how a red build
becomes background noise.)* A mutation the check does not
reject is a **survivor**, and a survivor is the interesting output: it means the
check passes on a tree that is wrong in exactly the way the check exists to
prevent.

The expectation is that some survive. 1.6.0's expectation was that hollow checks
would be rare and fourteen were found; the honest posture here is that the number
is unknown.

**Stop if** the survivor count is large enough that fixing them is a second
cycle. Then the deliverable is the corpus, the survivor list, and a schedule —
the same shape V1 took, and the same reason.

**X3 — every public trait, not one.** *(Done: four traits, four fixtures, each
verified strict. The stop condition did not trigger — every one of them is
implementable from outside.)* V1 Finding 6 records that
`cargo semver-checks` does not catch a required method added to a public trait,
and that `tests/compile_pass/profile_is_implementable.rs` covers `Profile` and
nothing else. Enumerate the public traits an outside crate can implement and
give each the same fixture, or record why it needs none.

**Stop if** the enumeration shows most public traits are unimplementable outside
the workspace — that is a finding about the API's shape and belongs in
`ROAD-TO-2.0.md` rather than in a pile of fixtures.

### Done when

Every check either rejects a recorded mutation, or is listed as not doing so with
a reason. The survivor list exists whether or not it is empty.

**All three landed.** The survivor list is empty because the one survivor was
fixed; four checks are listed as hand-verified with their reasons; the corpus
runs in CI.

### Explicitly not in scope

- **Anything breaking.** `cargo semver-checks` runs against the published 1.6.0,
  with Finding 6's caveat about what that does not cover.
- **Mutation testing of the library.** This is about the *checks*, not about
  `ucal-core`'s arithmetic. Mutating the arithmetic and watching the test suite
  is a different and much larger exercise, and the conformance vectors already
  cover the part of it that matters most.
- **Z2's remaining wall-clock items** — several dials, `--tier`, `--since`. Small,
  optional, and not what this cycle is about.
- **W3, the third locale**, still postponed pending a choice of language.

## Breaking

_none, and none is permitted._

## Added

- **A downstream implementor for every public trait** (X3). The workspace has
  four — `Profile`, `TickInt`, `CalendarIdentity`, `LegacyCalendar` — all four
  are implementable from outside, and each now has a compile-pass fixture that
  fails when a required method is added. That is the change `cargo semver-checks`
  passes (V1 Finding 6).
- **A defect corpus** (X1): `cargo run -p xtask -- corpus`. Twenty recorded
  mutations, one per check, run against a sandbox copy of the tree so the real
  one is never edited. Four verdicts, three of them failures — a mutation that
  *survives*, one that edits nothing, and a check that was already failing before
  the mutation. Nineteen caught, one survivor.

## Changed

- **`citations` reads the documentation.** It walked Rust source only and now
  covers `Documentation/`, `spec/` and `docs/` as well — 126 distinct citations
  became **136**, across 43 Markdown files carrying 502 citation sites that had
  never been checked.
- **`version-lockstep` reads member manifests**, and requires
  `version.workspace = true` rather than merely a matching number.
- **`xtask lint` skips `compile_pass/`** as it already skipped `compile_fail/`.
  Trybuild fixtures are separate crates compiled to check that something does or
  does not build; the shipped rules do not apply to them.

## Fixed

- **Two dangling citations that had never been seen**, surfaced the moment the
  scan widened. A reference to section 29 — cited twice, in `spec/RULES.md` and
  the 0.5.0 release note — where the specification ends at §24. It had stood for
  four releases inside a sentence whose entire point is *that review is not
  enough, and the rule left to review is the one that failed*. It cites §21.3
  now, which is where the spec makes that argument.
- **The corpus's own first mutation planted a dangling citation in the tree under
  test**, and `check-docs` failed on the real repository as a result. Caught by
  the citation check, on the file that was about to test it.

## What this cycle found out about itself

**The checks that exist mostly work.** Twenty-one mutations, one survivor — a far
lower rate than 1.6.0's fourteen hollow checks out of twenty-three, and worth
saying plainly rather than treating as a triumph. 1.6.0 found checks that were
not *connected* to anything; that is a different failure and was much more
common than a check that is connected and wrong.

**The one survivor was the one that mattered.** `citations` covered the source
and not the documentation — the place where citations are written by hand rather
than by someone with the spec open, and the surface a reader checks the project
against. Widening it immediately found a broken reference four releases old,
sitting in a sentence about review not being enough.

**The fix has a cost, and it was paid four times while paying it.** A broken
citation can no longer be quoted: writing one out turns the page explaining it
into a second instance. That happened in the corpus source, in `RULES.md`, in the
X1 proposal's survivor paragraph, and once more in the paragraph written to
describe the cost — in the sentence describing it. The check caught all four.

**And two process failures, both mine.** I ran the test suite filtered to what I
had just written rather than the whole thing, and CI found five tests I had
broken. Then `cargo fmt` reformatted twelve files in a repository with no
rustfmt config and no fmt job — two hundred lines of churn attached to a
fourteen-line fix. A test run narrowed to what you changed tells you about what
you changed and nothing about what you broke.

## Carried forward from 1.6.0

- **The three asks in [`CONTACT.md`](../CONTACT.md)** are open, wanted, and a
  condition on nothing shipping.
- **`cargo semver-checks` may have blind spots beyond the one that is measured.**
  V1 Finding 6 established that it misses a required method added to a public
  trait; X3 covered all four such traits with compile-pass fixtures. Whether it
  misses anything in another category — enums, struct fields, generic bounds,
  lifetimes — is **unmeasured**, and finding out means an external probe per
  category of breaking change.
- **The 2.0 bundle**, decided in `ROAD-TO-2.0.md` and not scheduled: withdraw
  `bigint` from the public feature surface, move the data model to `Cow`, give
  `Measured` a sign, and implement §15.1 in the library.
- **`--all-features` cannot build this workspace**, because it enables both
  backends and the guard fires. Three tools want something the feature surface
  cannot give them.
- **§15.1 is `UNIMPLEMENTED`** for `ucal-body` (D-A20). Both loaders live in the
  binary and say so.
- **`check-links` is not in CI**, deliberately: a job that fails when somebody
  else's web server is down trains people to ignore red. The cost is that nothing
  automatic notices when a cited URL rots, and it is run at each release, which
  is a procedure and not a mechanism.
- **Three single-site conditions still share codes with other meanings** (D-A24):
  a build without a feature, an unreachable dispatch arm. A second site of either
  is the trigger to name it.
- **A rounded parameter is a different calendar**, for every body-file parameter
  that is not `derived:`.
- **Ten of the twelve derived calendars have no anchor**, which is the ordinary
  case and not a gap.
- **[`GE-U4-walk.sh`](../Proposals/GE-U4-walk.sh) is built and unrun.**
- **W3, a third locale**, postponed with its reason recorded.
- **The signing key has no authority behind it that is not the author**, and the
  release checksums are not signed.
- **Eight commits in the history are unsigned**, permanently.
