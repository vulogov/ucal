## The goal of this cycle: every number says what it is

**Every number this program prints should say what kind of number it is, and
anyone holding the binary should be able to check it.**

The project's claim is unusually strong: every quantity is exact, or a certified
enclosure, or a declared rounding. The *output* does not say which. Here is the
defect that anchors the cycle, from `ucal ladder`:

```
tier   exponent  name              beats                      seconds (bridge)
T5     85        deep / deeps      298023223876953125.000000  13936046862139962.492833
T-3    45        spark / sparks                     0.000000                  0.000000
```

Three different kinds of number, rendered identically, with the mode undeclared
in all three cases.

`T5` in **beats** is exact. A tier is a whole power of five of the beat, so above
`T0` the expansion terminates at once and those six zeros are the value.

`T-3` in **beats** is a rounding — and rounds to something a reader will misread.
`5^45 / 5^60 = 5^-15 ≈ 3.2768 × 10^-11`. That expansion is *finite*, because the
denominator is a power of five, but it is fifteen places long, and six digits
render it `0.000000`. **Four tiers do this**, and nothing in the output says the
value is not zero.

**Bridge seconds** never terminate at any digit count. `5^e / SECOND` carries
`18 548 584 399 861` in its denominator, which is neither a power of two nor of
five — checked at 6, 30 and 60 digits.

The first is a labelling gap. The second is an accuracy defect that shipped, and
it is why V2 is not merely tidiness: at six digits there is no way to see a
tick's length in beats at all.

That is one instance of a general gap. `to-civil` treats rounding as a choice —
`--round` selects it and the output reports it, because Rule R says rounding
happens only at rendering and a rendering choice is a choice. Everywhere else
the digit count and mode are hardcoded at twelve call sites and never reported.

### Scope

**V1 — A certification tag on every rendered number. _(blocker for V2)_**

Three kinds, which is what the code already does and the output already hides:

| tag | meaning |
|---|---|
| `exact` | the expansion terminates **within the digits printed**; they are the value |
| `rounded` | the printed digits are a rounding, with the mode and digit count that produced it |
| `enclosure` | one bound of a certified pair; the value lies between this and its partner |

`exact` is a claim about *this rendering*, not about the number in the abstract.
`5^-15` has a finite expansion and is still a rounding at six digits, and that
distinction is the whole reason the tag is computed from the value at render
time rather than annotated by hand.

The vocabulary must be uniform across commands, because its whole purpose is to
let a reader stop asking per-field. `--json` gains the tag alongside the value;
text mode shows it where it is not obvious.

**V2 — `--digits` and `--round` become global options. _(depends on V1)_**

Rule R makes rounding a declared choice. `to-civil` already treats it as one;
twelve other call sites hardcode it. The current values become the defaults, so
nothing changes for a caller who does not ask, and a caller who wants twenty
digits of the bridge conversion can have them.

The point is not configurability. It is that a hidden constant in a rendering
path is an undeclared choice, and this project's whole position is that
undeclared choices are how exactness leaks away.

**V3 — `ucal verify`: the binary checks its own constants.**

`xtask` re-derives `BEAT`, `SECOND`, `ORIGIN_OFFSET`, the claim half-width and
every fixture, by two independent integer routes, and checks §2.4's invariants.
A user with a released binary cannot do any of that — they get compiled-in
constants and a promise.

`ucal verify` re-executes the provenance chain at runtime and compares each
derived constant against the compiled-in value, reporting them one by one. It
turns *trust this binary* into *this binary checks itself*.

**Its limit must be stated in its own output, not here.** It can only derive
along the *one* backend that was compiled in: `backend.rs` carries
`compile_error!("exactly one of the u512 or bigint features must be enabled")`,
so the two-route cross-check that gives Rule W its force is a build-time
property of the test suite and is **not reachable at runtime, ever**. Making it
reachable would mean shipping both backends behind a dispatching type, which
costs `Copy` and const-constructibility — the two properties D-4 chose the
default backend *for*. That trade is not worth making, so the honest move is to
say so where a user will read it.

**V4 — An audit trail for a computed value.**

`ucal datum` prints `datum_provenance.chain[]`: every arithmetic step from the
published age to `ORIGIN_OFFSET`, re-executable, and `xtask` re-executes it.
Nothing else in the program does this.

`ucal cosmo age --audit` would print how its enclosure was reached — the
substitution, the panel count, where each directed rounding was applied and in
which direction, and how the two bounds accumulated. A *summary*, not a trace: a
depth-12 run is 4096 panels and a per-panel dump is not an audit, it is a
haystack.

**V5 — Interval inputs.**

The machinery is interval-valued throughout and only ever accepts a point.
`--z 1090..1110` would let a caller carry their own uncertainty through a
computation instead of picking a midpoint and losing it — which is precisely the
move the project spends thirty chapters objecting to when other people make it.

**V6 — Make the tags load-bearing rather than decorative.**

Two properties, both mechanical:

- anything tagged `exact` must reparse to the same value, exactly;
- every emitted enclosure must satisfy `lo ≤ hi` and a non-negative width,
  asserted at the point of emission rather than hoped for.

Without these, V1 is a label. With them, it is a claim.

**D1 — Continuous integration.**

There is none. The verification block is a list a person runs, which has held
because one person works here and runs it — the property that stops being true
first. Both backends, the wasm target, `-D warnings`, and the four `xtask`
checks, on every push.

The honest caveat: CI on a single-contributor repository mostly protects against
that contributor. Not a small thing — several defects this cycle and last were
found by running something rather than reading it — but it should be claimed at
its real size.

**D3 — Check the CLI manual's contents, not only its surface.**

`check-docs` verifies that every command and global option in
`Documentation/CLI.md` exists and that nothing documented has been removed. It
does not check the 86 **field** descriptions, which are the reason the file
exists.

The check was already run once by hand, at 0.3.0's close, and found two errors:
`arithmetic_width` and `parameter_width` name Rust struct fields that never
appear in any output, where the emitted names are `widths.arithmetic_years` and
`widths.parameter_years`. A check that finds real defects the first time it runs
should not depend on someone thinking to run it.

It can verify that every documented field name appears in some command's real
`--json` output, and that every emitted field name is documented. It cannot
verify that the prose is *true*. That limit belongs in the check's own output.

**D5 — Titan's anchor.**

Carried since 0.2.0 (GE-3). `titan-d` is structurally complete — units,
intercalation, cycles — and unusable for dating, because a calendar's *phase*
needs an anchor and no published convention exists to cite. It will not get one
by invention. The work is to look for a citable convention; if there is none,
the outcome is that the entry stays as it is, saying so, and that is recorded as
the result rather than as a failure to finish.

### Ordering

V1 → V6 → V2 → V4 → V3 → V5, with D1, D3 and D5 independent of all of them.

V1 first because V2 has nothing to report without it. V6 immediately after,
because a tag nobody checks is worse than no tag — it invites a reader to trust
it. D1 early if it is taken at all, since everything after it gets checked for
free.

### Done when

- Every numeric field in `--json` carries a certification tag, and the two
  properties in V6 hold over every command's output.
- `ucal ladder` distinguishes its exact column from its rounded one without a
  reader having to know that `18 548 584 399 861` is neither a power of two nor
  of five.
- `--digits` and `--round` reach every rendering path, defaults unchanged.
- `ucal verify` re-derives the profile's constants and states, in its own
  output, that it does so along one backend and why the second is unreachable.
- Every field name in `Documentation/CLI.md` appears in some real output, and
  every emitted field name is documented, checked mechanically.
- Titan's anchor is either cited or recorded as absent with what was searched.

### Explicitly not in scope

- **The tier-scale navigator (GE-U4).** Postponed. The proposal stands with its
  kill criterion, and the cheapest test in it — a recorded walk rather than an
  interactive program — is still the thing to try first when it is picked up.
- **Shipping both integer backends in one binary.** See V3: it would cost `Copy`
  and const-constructibility, which is what D-4 chose the default backend for.
- **A UC-2 profile.** GE-6's kill criterion fired and D-21 stands.
- **Second-order quadrature.** C3, dropped in 0.3.0 with the measurement that
  killed it. Not reopened without new evidence.
- **Stabilising the API at 1.0.** Nothing has been used by anyone but the
  author, and 0.3.0's three breaking changes are what that promise would have
  cost.
- **A universal Cyrillic or Greek symbol layer.** Settled in 0.3.0's U5.
