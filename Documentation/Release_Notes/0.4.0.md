# 0.4.0 — UNRELEASED

In development on the `0.4.0` branch. `main` carries the released 0.3.0 line.

Nothing is published at this version. Entries below accumulate as work lands;
add to them in the same commit as the change, not on release day.

## The goal of this cycle: not yet chosen

0.2.0 had one stated goal — supersede the RFC. 0.3.0 had one — legibility. Both
worked because every scope item served it, and this file should not invent a
third to look decisive. The goal is recorded here once it is decided.

What follows is the candidate list. It is a menu, not a plan.

**Three of them share a theme**, and that is an observation rather than a
proposal. This project verifies unusually hard: 453 tests on two integer
backends, a `no_std` wasm build, four `xtask` checks, lints that fail on a
deliberate violation, and gated experiments whose kill criteria are recorded
when they fire. And **nothing runs any of it but a person who remembers to.**
The conformance vectors carry a digest and no signature. The newest document
has a check on its surface and none on its contents. D1, D2 and D3 are the same
gap seen from three sides: the checks are good and their *provenance* is
informal.

### Candidates

**D1 — Continuous integration.** There is none. `Documentation/Release_Notes`
prints the verification block and a human runs it; that has held so far because
one person works here and runs it, which is exactly the property that stops
being true first. The block is already written and already passes, so the work
is mechanical: both backends, the wasm target, `-D warnings`, and the four
`xtask` checks, on every push.

The honest caveat: CI on a repository with one contributor mostly protects
against that contributor. That is not a small thing — three defects this cycle
were found by running something rather than reading it — but it should be
claimed at its real size.

**D2 — Sign the conformance vectors.** Carried since 0.2.0.
`xtask -- verify-vectors` re-derives the vectors along both integer routes and
checks them against `fixtures/SHA256SUMS`, then reports **UNSIGNED**, because a
digest proves a file was not corrupted and only a signature proves who stood
behind it. `spec/CONFORMANCE.md` documents how to make and check one; nobody has.
Small, and it closes the one place the tooling currently says "I cannot vouch
for this" out loud.

**D3 — Check the CLI manual's contents, not only its surface.**
`check-docs` verifies that every command and global option in
`Documentation/CLI.md` exists and that nothing documented has been removed. It
does not check the 86 **field** descriptions, which are the reason the file
exists.

This is a candidate because the check was already run once, by hand, at 0.3.0's
close — and it found two errors: `arithmetic_width` and `parameter_width` are
Rust struct fields that never appear in any output, where the emitted names are
`widths.arithmetic_years` and `widths.parameter_years`. A check that finds real
defects the first time it is run is a check that should not depend on someone
thinking to run it.

What it can verify is that every documented field name appears in the real
`--json` output of some command, and that every emitted field name is
documented. What it cannot verify is whether the *prose* is true. That limit
should be stated in the check's own output rather than left for a reader to
assume away.

**D4 — GE-U4: decide, and test the cheap thing first.**
[The proposal](../Proposals/GE-U4-tier-navigator.md) scopes a tier-scale
navigator with its kill criterion written first, and records three conditions
under which it should not be built. The third is the one to act on: *the claim
that this must be interactive is a hypothesis.* A recorded walk through the
ladder — the same zoom, as an animation or a sequence of stills — tests the
same idea for an afternoon rather than a dependency tree, and if it works
recorded then interactivity was never the load-bearing part.

So the candidate is not "build the TUI". It is "run the cheaper experiment that
tells you whether to".

**D5 — Titan's anchor.** Carried since 0.2.0 (GE-3). `titan-d` is structurally
complete — units, intercalation, cycles — and unusable for dating, because a
calendar's *phase* needs an anchor and there is no published convention to cite.
It will not get one by invention. This is a candidate only in the sense that
somebody could go and find a citable convention; if none exists, the honest
outcome is that the entry stays as it is, saying so.

### Explicitly not in scope

- **A UC-2 profile.** GE-6's kill criterion fired and D-21 stands. Settled in
  0.2.0.
- **Second-order quadrature.** C3, dropped in 0.3.0 with the measurement that
  killed it: the `z_of_t` wall is at step 125 with a 37-digit denominator at
  depth 4, 8 and 12 alike, so it is a property of the 512-bit domain and no
  quadrature moves it. Not reopened without new evidence.
- **Stabilising the API at 1.0.** Nothing has been used by anyone but the
  author. A stability promise made without a user is a promise about a guess —
  and 0.3.0's three breaking changes are what that guess would have cost.
- **A universal Cyrillic or Greek symbol layer.** Settled in 0.3.0's U5:
  Appendix D's criterion and the homoglyph decision already embedded in the UCID
  alphabet both rule against it. Cyrillic short forms ship inside the `ru`
  locale, where the stated locale makes invariance structural.

Run before each entry lands, not only at release:

```
cargo test --workspace --release

  --features bigint,std,ucal-civil/hifitime,ucal/civil,ucal/body,ucal/events,ucal/cosmo

cargo build -p ucal-core --target wasm32-unknown-unknown \
  --no-default-features --features u512
cargo run -p xtask && cargo run -p xtask -- lint \
  && cargo run -p xtask -- check-docs && cargo run -p xtask -- verify-vectors
```

clean, wasm `no_std` green, lints clean with two declared exemptions, generated
docs current, 114 citations resolving, `Documentation/CLI.md` covering the CLI
surface, vectors re-deriving to the committed digest.

## Carried forward from 0.3.0

Open items, none of them regressions. Recorded so the cycle starts with them
visible rather than rediscovered.

- **Titan has no anchor.** See D5.
- **The conformance vectors are unsigned.** See D2.
- **Eight commits in the history are unsigned.** Removing the co-authorship
  trailers from 0.2.0's history required rewriting those commit messages, and
  that drops signatures with no way to restore them without changing the hashes
  again. The four release tags are signed and verify; the rewritten commits
  cannot be. This one is not a candidate — it is permanent, and it is recorded
  because a reader checking signatures will find the gap and deserves to know
  what made it.
- **GE-A4, the two-reader test, has not been run.** The protocol is in
  [`GE-A4-reader-test.md`](../LIFE_UNIVERSE_AND_GOD/GE-A4-reader-test.md), and
  the book's dual-audience claim is untested until two people who are not the
  author run it. The same shape as GE-U4's protocol, and the same obstacle.
- **`Documentation/CLI.md`'s prose is unverified.** See D3.
