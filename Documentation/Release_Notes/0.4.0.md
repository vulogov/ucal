# 0.4.0 — 2026-08-04

Every number says what it is, and no Earth unit appears outside an Earth context
unless it is asked for.

Five things break, each with what to write instead. Two experiments ran. One
amendment to the specification, D-A16. And the first CI run found a defect the
local verification block could not see, which was the point of building it.

## The goal of this cycle: every number says what it is

**Every number this program prints should say what kind of number it is, and
anyone holding the binary should be able to check it.**

The project's claim is unusually strong: every quantity is exact, or a certified
enclosure, or a declared rounding. The *output* does not say which. Here is the
defect that anchors the cycle, from `ucal ladder`:

```
tier   exponent  name              beats                      seconds (bridge)
T5     85        deep / deeps      298023223876953125.000000  13936046862139962.492833
T-3    45        spark / sparks                     0.000000                  0.000000
```

Three different kinds of number, rendered identically, with the mode undeclared
in all three cases.

`T5` in **beats** is exact. A tier is a whole power of five of the beat, so above
`T0` the expansion terminates at once and those six zeros are the value.

`T-3` in **beats** is a rounding — and rounds to something a reader will misread.
`5^45 / 5^60 = 5^-15 ≈ 3.2768 × 10^-11`. That expansion is *finite*, because the
denominator is a power of five, but it is fifteen places long, and six digits
render it `0.000000`. **Four tiers do this**, and nothing in the output says the
value is not zero.

**Bridge seconds** never terminate at any digit count. `5^e / SECOND` carries
`18 548 584 399 861` in its denominator, which is neither a power of two nor of
five — checked at 6, 30 and 60 digits.

**None of this is floating point, and none of it is lost accuracy.** Rule E
forbids a float token in any shipped crate and the lint enforces it; the tree's
one exemption is a marked `#[cfg(test)]` oracle in `ucal-cosmo`. These strings
come from `Ratio::to_decimal_string`, which computes
`mul_div_rounded(num, 10^digits, den, mode)` — one integer multiply-divide with
an explicit mode — and inserts a `.` into the resulting integer's digits. A tick
in beats is held exactly as `1 / 5^60` and renders exactly at sixty digits:
`0.000000000000000000000000000000000000000001152921504606846976`.

So the defect is precisely where the design says information may be lost, and
nowhere else. Rule R makes rendering the only site at which a value may be
rounded, and this is that site working as specified while failing to say so.
V1 and V2 add no precision, because there is none to add: they make the
rendering declare what it did, and give the digit count to the caller. That is
why V2 is not tidiness — at six digits there is currently no way to ask for a
tick's length in beats at all.

That is one instance of a general gap. `to-civil` treats rounding as a choice —
`--round` selects it and the output reports it, because Rule R says rounding
happens only at rendering and a rendering choice is a choice. Everywhere else
the digit count and mode are hardcoded at twelve call sites and never reported.

### Scope

**V1 — A certification tag on every rendered number. _(blocker for V2)_**

Three kinds, which is what the code already does and the output already hides:

| tag | meaning |
|---|---|
| `exact` | the expansion terminates **within the digits printed**; they are the value |
| `rounded` | the printed digits are a rounding, with the mode and digit count that produced it |
| `enclosure` | one bound of a certified pair; the value lies between this and its partner |

`exact` is a claim about *this rendering*, not about the number in the abstract.
`5^-15` has a finite expansion and is still a rounding at six digits, and that
distinction is the whole reason the tag is computed from the value at render
time rather than annotated by hand.

The vocabulary must be uniform across commands, because its whole purpose is to
let a reader stop asking per-field. `--json` gains the tag alongside the value;
text mode shows it where it is not obvious.

**V2 — `--digits` and `--round` become global options. _(depends on V1)_**

Rule R makes rounding a declared choice. `to-civil` already treats it as one;
twelve other call sites hardcode it. The current values become the defaults, so
nothing changes for a caller who does not ask, and a caller who wants twenty
digits of the bridge conversion can have them.

The point is not configurability. It is that a hidden constant in a rendering
path is an undeclared choice, and this project's whole position is that
undeclared choices are how exactness leaks away.

**V3 — `ucal verify`: the binary checks its own constants.**

`xtask` re-derives `BEAT`, `SECOND`, `ORIGIN_OFFSET`, the claim half-width and
every fixture, by two independent integer routes, and checks §2.4's invariants.
A user with a released binary cannot do any of that — they get compiled-in
constants and a promise.

`ucal verify` re-executes the provenance chain at runtime and compares each
derived constant against the compiled-in value, reporting them one by one. It
turns *trust this binary* into *this binary checks itself*.

**Its limit must be stated in its own output, not here.** It can only derive
along the *one* backend that was compiled in: `backend.rs` carries
`compile_error!("exactly one of the u512 or bigint features must be enabled")`,
so the two-route cross-check that gives Rule W its force is a build-time
property of the test suite and is **not reachable at runtime, ever**. Making it
reachable would mean shipping both backends behind a dispatching type, which
costs `Copy` and const-constructibility — the two properties D-4 chose the
default backend *for*. That trade is not worth making, so the honest move is to
say so where a user will read it.

**V4 — An audit trail for a computed value.**

`ucal datum` prints `datum_provenance.chain[]`: every arithmetic step from the
published age to `ORIGIN_OFFSET`, re-executable, and `xtask` re-executes it.
Nothing else in the program does this.

`ucal cosmo age --audit` would print how its enclosure was reached — the
substitution, the panel count, where each directed rounding was applied and in
which direction, and how the two bounds accumulated. A *summary*, not a trace: a
depth-12 run is 4096 panels and a per-panel dump is not an audit, it is a
haystack.

**V5 — Interval inputs.**

The machinery is interval-valued throughout and only ever accepts a point.
`--z 1090..1110` would let a caller carry their own uncertainty through a
computation instead of picking a midpoint and losing it — which is precisely the
move the project spends thirty chapters objecting to when other people make it.

**V6 — Make the tags load-bearing rather than decorative.**

Two properties, both mechanical:

- anything tagged `exact` must reparse to the same value, exactly;
- every emitted enclosure must satisfy `lo ≤ hi` and a non-negative width,
  asserted at the point of emission rather than hoped for.

Without these, V1 is a label. With them, it is a claim.

**D1 — Continuous integration.**

There is none. The verification block is a list a person runs, which has held
because one person works here and runs it — the property that stops being true
first. Both backends, the wasm target, `-D warnings`, and the four `xtask`
checks, on every push.

The honest caveat: CI on a single-contributor repository mostly protects against
that contributor. Not a small thing — several defects this cycle and last were
found by running something rather than reading it — but it should be claimed at
its real size.

**D3 — Check the CLI manual's contents, not only its surface.**

`check-docs` verifies that every command and global option in
`Documentation/CLI.md` exists and that nothing documented has been removed. It
does not check the 86 **field** descriptions, which are the reason the file
exists.

The check was already run once by hand, at 0.3.0's close, and found two errors:
`arithmetic_width` and `parameter_width` name Rust struct fields that never
appear in any output, where the emitted names are `widths.arithmetic_years` and
`widths.parameter_years`. A check that finds real defects the first time it runs
should not depend on someone thinking to run it.

It can verify that every documented field name appears in some command's real
`--json` output, and that every emitted field name is documented. It cannot
verify that the prose is *true*. That limit belongs in the check's own output.

**D5 — Titan's anchor.**

Carried since 0.2.0 (GE-3). `titan-d` is structurally complete — units,
intercalation, cycles — and unusable for dating, because a calendar's *phase*
needs an anchor and no published convention exists to cite. It will not get one
by invention. The work is to look for a citable convention; if there is none,
the outcome is that the entry stays as it is, saying so, and that is recorded as
the result rather than as a failure to finish.

### Ordering

V1 → V6 → V2 → V4 → V3 → V5, with D1, D3 and D5 independent of all of them.

V1 first because V2 has nothing to report without it. V6 immediately after,
because a tag nobody checks is worse than no tag — it invites a reader to trust
it. D1 early if it is taken at all, since everything after it gets checked for
free.

### Done when

- Every numeric field in `--json` carries a certification tag, and the two
  properties in V6 hold over every command's output.
- `ucal ladder` distinguishes its exact column from its rounded one without a
  reader having to know that `18 548 584 399 861` is neither a power of two nor
  of five.
- `--digits` and `--round` reach every rendering path, defaults unchanged.
- `ucal verify` re-derives the profile's constants and states, in its own
  output, that it does so along one backend and why the second is unreachable.
- Every field name in `Documentation/CLI.md` appears in some real output, and
  every emitted field name is documented, checked mechanically.
- Titan's anchor is either cited or recorded as absent with what was searched.

## Breaking

**No Earth unit appears outside an Earth context unless you ask for one.**
`--bridge` is the request; without it, output uses ticks and the tier ladder.

What disappears from default output, and where to find it:

| was | now |
|---|---|
| `explain`'s `si_bridge` | `ucal explain --bridge` |
| `ladder`'s `seconds (bridge)` column | `ucal ladder --bridge` |
| `cosmo age`'s `lo_years` / `hi_years` / `*_years` widths | `--bridge`, or read `lo_ticks` / `at_drift` / `*_ticks` / `*_drifts` |
| `cosmo z`'s `years_after_datum` | `--bridge` |
| `cosmo model`'s `hubble_time.gyr` | `--bridge` |
| `events show`'s `width_years` | `--bridge`, or `width_ticks` |
| `datum`'s `implied_age.seconds` | `--bridge` |

And one field is renamed. `timeline`'s `T4s since the datum` becomes
`tiers_since_datum`: the old key changed with `--tier`, so `--tier arc` gave
`T1s since the datum` and no consumer could write an accessor that survived a
flag. Which tier it is was always in the document's own `tier` field, and now
that is the only place it lives.

`to-civil`, `from-civil` and `datum`'s provenance chain are unchanged: the first
two *are* Earth calendar commands, and the third is what §19.2 requires and what
records where an Earth-sourced measurement entered.

This amends §4.3 — "`ucal explain` always prints the SI equivalent alongside" —
recorded as **D-A16 (AMENDMENT)** in `spec/SPEC-DELTAS.md`.

While the crates are `0.x`, this section is permitted to have contents and a
minor bump is permitted to break the API. Anything landing here must say what
stops compiling and what to write instead. 0.3.0 opened with this section
reading "none yet" and closed with three entries, none of which had been
noticed until the section was checked rather than assumed — so it is checked
before the file is dated, not after.

## Added

- **V1: a certification on every rendered number.** `Certification` is `exact`,
  `rounded` (with mode and digit count) or `enclosure`, and it is **computed from
  the value at render time** — `Ratio::terminates_at` asks whether
  `n × 10^digits` divides `d` — rather than annotated by hand and able to drift.

  `Value::quantity` is now the only way to render a rational in the CLI crate.
  Documents carry a `certification` map listing **only the exceptions**, in both
  `--json` and text, because exactness is the expectation and a field's absence
  from the map is therefore a statement.

  Additive: existing JSON fields keep their names, shapes and values, so
  `ucal-json/1` still describes the document. `Documentation/CLI.md` now states
  that stability means existing fields are fixed and new ones may appear.

- **V6: three properties that make the tag a claim.** Anything called `exact`
  reparses to the value it prints; the map lists every non-exact quantity and
  nothing else; and **no rendered decimal reaches the output without going
  through the certified constructor.**

  The third found two on its first run — `widths.arithmetic_years` and
  `widths.parameter_years` in `cosmo age` were formatted straight into
  `Value::text` and carried no certification. Both now go through
  `years_quantity`. It has a short exemption list for text that only looks like
  a rendered rational: a civil label's fractional second, and figures reproduced
  verbatim from a source, where certifying would mean certifying someone else's
  rounding.

  Verified strict by injection: reverting a render site to `Value::text` fails
  the bypass property, and making `of_ratio` always answer `Exact` fails three
  of the eight.

- **`cosmo age`'s widths were reported in Earth years and nothing else.** The
  enclosure gave ticks *and* years; the three widths gave only years — a Julian
  year being 365.25 of Earth's rotations, used as the sole measure of an epoch
  13.4 billion years before Earth existed, by the one program written to object
  to exactly that.

  §4.3 and Rule A.5 permit the bridge unit as *informative*, shown **alongside**
  and never **instead**. Each width is now given in ticks, in drifts and in
  years, in that order, and `YEAR_DEFINITION` says plainly that a Julian year is
  an Earth unit and that the tick counts are the answer.

- **Every command that prints a year now says which year.** The Julian year,
  `31 557 600 s` exactly — the same definition `ucal datum` already declared for
  `Gyr`, and which `cosmo age`, `cosmo model`, `cosmo z` and `events show` used
  without saying.

  Not a nicety. "Years" is ambiguous by about `2 × 10^-5` between Julian,
  Gregorian and tropical, and at the ages this command reports that is **eight
  years on 371 600** — while `arithmetic_years` prints to one decimal. The
  ambiguity landed in digits a reader could see, not below them.

- **[`ROAD-TO-1.0.md`](../Proposals/ROAD-TO-1.0.md)** — five cycles, with the
  evidence each is built from. The finding that shapes it: of twenty-four rules,
  two were enforced by convention alone, and **every alignment defect found by a
  human in 0.3.0 and 0.4.0 landed on one of them.** The type-enforced rules did
  not leak. Rule R, enforced by review, leaked repeatedly — in a project whose
  central argument is that review is not enough.

- **D5: Titan's anchor — the search is specified, not completed.**
  [`D5-titan-anchor.md`](../Proposals/D5-titan-anchor.md) records what an
  `Anchor` needs, why six of its seven fields are trivial for Titan and the
  seventh is the whole problem, why an invented one is the narrowing GE-3's kill
  criterion forbids, and what a usable citation would have to contain.

  And it says what was **not** done: the planetary-science literature was not
  searched, because this cycle had no access to it. So this is not the negative
  result GE-3 wants — it is a statement that the search has not been done, with
  the search specified so that doing it is bounded. Claiming "no convention
  exists" would be an overclaim; what can be said is that none is cited here and
  none was found in what was available to look at.

- **D3: the CLI manual's fields are checked, not just its surface.**
  `crates/ucal/tests/manual_fields.rs` fails when a field the manual documents
  is emitted by no command, or a field a command emits is documented nowhere.

  It found **35 undocumented fields** on its first run — the manual covered the
  headline ones and not the leaves of `cal show`, `events show`, `cosmo model`
  or `to-civil`. All are documented now.

  It states its own limit, and there is a test that the limit stays stated: the
  manual is verified **complete and current**, not **correct**. Whether a
  description says something true is not mechanically checkable, and claiming
  otherwise would be the overclaim the rest of the project exists to prevent.

- **V5: `--z` accepts an interval.** `ucal cosmo age --z 1090..1110`. The
  machinery is interval-valued end to end and until now would only accept a
  point, so a caller carrying their own uncertainty had to pick a midpoint and
  lose it — the move the book spends thirty chapters objecting to when other
  people make it.

  `t` is decreasing in `z`, so the hull runs from the age at the largest `z` to
  the age at the smallest. Appendix H.4 requires monotonicity to be *asserted,
  not assumed*, so **the ordering is checked at runtime**: if the two enclosures
  do not sit as monotonicity says they must, that is `UCAL-E0070` rather than a
  hull that means nothing.

  And a **third width**. Rule X keeps arithmetic and parameter error apart
  because merging them hides which is doing the work; a caller's own uncertainty
  is a third thing and folding it into either would be the same mistake.
  `input_width` appears only for an interval input — always present and always
  zero would be noise, and its absence says the input was a point. A test
  asserts the three widths add up to the enclosure.

- **V4: `ucal cosmo age --audit`.** The substitution, why the panels use an
  interval extension rather than endpoints, the panel count, and then the
  direction each rounding moves — densities, roots, accumulation, the
  Hubble-time multiply, the tick quantisation. A summary and not a trace: a
  depth-12 run is 4096 panels doing the same four things.

  It lives in `ucal-cosmo` beside the code it describes rather than in the CLI,
  so a description cannot drift from the computation it narrates.

- **`no-indent-in-literal` lint.** A string literal wrapped across source lines
  without a `\` continuation keeps the next line's indentation *inside the
  string* and prints as a gap mid-sentence. 0.3.0 fixed one instance by hand;
  this cycle produced two more, including one in `C4_ACHIEVABLE_TOLERANCE`, so
  the sweep became a check.

  Getting it right took three attempts and each failure is instructive. It first
  ran on the projection holding string literals *and* non-doc comments, and
  flagged 134 aligned comment tables. Given its own `\0`-blanked projection it
  still flagged gaps *between* two literals on one line, because a space-blanked
  gap is indistinguishable from indentation inside a literal. And once that was
  fixed it silently passed a deliberately broken literal — the run follows the
  literal's own newline, and requiring content immediately before it caught only
  the other shape. Both shapes are now caught, and a proper `\` continuation is
  not, which is the distinction the whole lint turns on.

- **V2: `--decimals <N>` and `--round <MODE>`, global.** Without them every field
  keeps the precision it was written with, so the default output is unchanged —
  checked by a test that renders each document with and without an absent
  override and compares.

  What made this work was moving *when* a value is rendered. `Value::Quantity`
  now carries the **exact rational** rather than a string, and renders at the
  last possible moment. Rule R makes rendering the only site at which a quantity
  may lose information; carrying the value there means the caller can reach that
  site instead of a constant reaching it first.

  So the tick's length in beats becomes askable:

  ```
  $ ucal ladder --named-only | grep T-12
  T-12  0   tick / ticks   0.000000

  $ ucal ladder --named-only --decimals 60 --json | jq -r '.tiers["T-12"].beats'
  0.000000000000000000000000000000000000000001152921504606846976
  ```

  And the certification follows the digit count, which is the two features
  meeting: at sixty digits `beats` becomes exact and leaves the map, while
  `seconds (bridge)` stays in it at 6, 60 and 120 digits alike, because it never
  terminates at any count.

  `to-civil`'s `--round` is now the global one — same vocabulary, same
  `half-even` default, so nothing changes for a caller. Its `--digits` stays
  separate and is documented as such: a civil label's sub-second precision is a
  format request, not a rounding policy for rationals.

## Fixed

- **The cosmology enclosure could exclude a value it had correctly bounded.**
  Quantising to ticks is the last rounding in the chain and has to widen like
  every one before it — lower bound down, upper bound up. Both were floored, and
  flooring the upper bound moves it *inward* by up to a tick.

  One tick against an enclosure `1.6 × 10⁵⁵` ticks wide is nothing numerically
  and fatal to the word *provably*, which is the only claim the type makes.
  `Ratio::ceil` is added as `floor`'s companion, with a doc comment saying why
  the two are not interchangeable at the end of an interval computation. The
  reported width at `z = 1100, depth 6` goes up by exactly one tick.

  **Found by writing V4's audit** and asking, for each step in turn, which
  direction it rounds. Nine steps answered "outward"; the tenth did not.
