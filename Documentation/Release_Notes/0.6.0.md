# 0.6.0 — UNRELEASED

In development on the `0.6.0` branch. `main` carries the released 0.5.0 line.

Nothing is published at this version. Entries below accumulate as work lands;
add to them in the same commit as the change, not on release day.

## The goal of this cycle: know exactly what 1.0 would freeze

0.5.0 closed the last rule enforced by convention. What remains before a version
number can promise anything is knowing **what** is being promised — and that is
not a matter of judgement so much as of enumeration. Nobody has counted the
surface.

The count, taken at the cycle's open:

```
public types with public fields or variants
  and no #[non_exhaustive]:                     39
```

**Every one of those is a decision that 1.0 makes permanent.** Marking a type
`#[non_exhaustive]` after 1.0 is a breaking change; leaving it unmarked means any
future field or variant is a breaking change. There is no third option and no
way to defer: shipping 1.0 without deciding *is* deciding, for all thirty-nine,
in the direction nobody chose.

### Scope

**S1 — The API audit. _(done)_**

Three questions per public item, and the third is the one that takes the time.

*Should it be `pub` at all?* Some of these are internal shapes that escaped.

*Should it be `#[non_exhaustive]`?* Not a default. `Rounding` is a closed set of
four modes and an exhaustive match on it is something a caller *should* be able
to write; `Event` is a catalogue entry that will gain fields. The answer differs
per type and the reasoning is what needs recording, because in five years the
mark will be read as deliberate whether or not it was.

*What does a caller do with it?* A type nobody can construct and nobody can
match on is not an API, and three of the four `#[non_exhaustive]` marks added in
0.3.0 and 0.4.0 were added *reactively*, after a field broke something. Doing
the rest reactively means doing them after 1.0, which is the one time it is not
allowed.

**S2 — Write down what 1.0 means here. _(done)_**

Semver is the floor and it is not the interesting part. This project makes
claims semver has no vocabulary for:

- `BIG_BANG_CLAIM` never acquires an arithmetic operator;
- a certified enclosure never narrows between versions without the model
  changing, and never silently;
- `ucal-json/1` fields never change name, shape or meaning — new ones may
  appear, which is the contract `Documentation/CLI.md` already states;
- a rounding never becomes undeclared again;
- no Earth unit reappears outside an Earth context by default.

Those are the promises worth freezing. They are also the ones a reader would
assume from the book and never find written down.

**S3 — MSRV and deprecation policy. _(done)_**

`rust-version = "1.85"` with no stated policy for moving it. A 1.0 that silently
raises its MSRV in a patch release has broken something semver does not model.

**S4 — Feature-flag audit. _(done)_**

`u512` and `bigint` are mutually exclusive and say so with a `compile_error!`.
The rest — `alloc`, `std`, `hifitime`, `civil`, `body`, `events`, `cosmo` —
interact in ways only the test matrix knows, and the test matrix tests two
combinations out of a much larger space. Enumerate what is supported and fail
the rest loudly, rather than leaving a caller to discover an unsupported
combination as a confusing compile error.

### The gap S2 found

Of the five promises worth making, three had mechanisms already — the
compile-fail cases for `BIG_BANG_CLAIM`, the `rounding-is-declared` lint, and
`no_earth_units.rs`. The other two are about **change over time**, and every
check in this tree runs against a single version of the tree, so neither was
enforceable at all.

`json-surface.txt` closes the first. The second — that a certified enclosure
never narrows silently — is left resting on release-notes discipline, and
`STABILITY.md` says so. That discipline has caught a `Breaking` omission twice,
which is better than nothing and is not a mechanism.

### Done when

A document exists that a stranger could read to know what upgrading within 1.x
will and will not do to them — and every one of the thirty-nine types above has
a recorded decision rather than a default.

### Explicitly not in scope

- **Shipping 1.0.** That needs 0.7.0's contact, which is not this cycle's work
  and cannot be hurried by doing more of this cycle's work.
- **New features.** A cycle that freezes a surface is the wrong cycle to widen
  it.
- **Anything 0.5.0 settled.** No rule returns to convention.

## Breaking

**Twenty-nine public types are now `#[non_exhaustive]`.** A struct literal or an
exhaustive match on one stops compiling outside its defining crate. Which types,
and why each, is in [`STABILITY.md`](../STABILITY.md).

What to write instead:

| was | now |
|---|---|
| `Citation { source, locator }` | `Citation::new(source, locator)` — `const fn` |
| `Fmt { form, precision, .. }` | `Fmt::default().with_form(…).with_precision(…)` |
| an exhaustive `match` on `StatedAs` | add a `_` arm |
| a literal of any other record type | read its fields; the crates construct them |

Eleven vocabularies stay open on purpose, so an exhaustive match on them keeps
working — `Rounding`, `Form`, `Scale`, `CivilCalendar`, `Kind`, `Precision`,
`Sign`, `IntervalOrdering`, `Provenance`, `ColorChoice`, `Frame`. The reasons
are recorded in `xtask/src/lint.rs`.

This is the cycle's whole point arriving as a diff: 1.0 makes each of these
permanent in whichever direction it is left, so they are decided now, while a
break still costs nothing. This cycle exists to make deliberate choices about a surface
that has been accumulating by default, and some of those choices are breaks —
which is why they belong here and not after 1.0.

## Added

- **[`Documentation/STABILITY.md`](../STABILITY.md)** — what 1.0 will promise,
  what it will not, and what would make it dishonest. Written before 1.0 so the
  promise is a decision rather than a description of whatever happened to be
  true on the day.

  Five promises above the semver floor, **each naming the mechanism that keeps
  it** — because a promise with no mechanism is a convention, and 0.5.0 was
  spent removing the last two of those. Two of the five turned out to have no
  mechanism at all, because every check in this tree runs against *one* version
  and those two promises are about change *across* versions.

  One of the two is now closed; the other is listed with its weakness rather
  than quietly omitted.

- **`.github/workflows/features.yml`.** Builds all fifteen supported feature
  combinations and asserts that each *refused* combination names its reason —
  and, for the two-backend case, that the reason is the first error. The verify
  workflow tests two points in that space; this covers it.

- **An MSRV job**, pinned to 1.87, plus a check that the manifest still declares
  it.

- **`public-type-is-classified` lint.** Every public type with public fields or
  variants must be `#[non_exhaustive]` or listed in `CLOSED_VOCABULARIES` with
  the reason an exhaustive match is a feature. A new public type cannot arrive
  undecided, which is what would otherwise happen between now and 1.0.

  Its first version reported three types that have nothing to freeze — a unit
  struct and two tuple structs with private fields — because it read sixty lines
  past a one-line declaration and found the *next* item's fields.

- **`Citation::new`** (`const fn`) and a **`Fmt` builder**, so that two types
  callers must construct stay constructible now that they are
  `#[non_exhaustive]`.

- **`fixtures/json-surface.txt` and `json_surface.rs`** — a committed baseline of
  the `ucal-json/1` surface: 296 field paths with the JSON kind each serialises
  to. A removed path or a changed kind fails; **an added path does not**, which
  is the contract rather than a convenience.

  Regenerated deliberately with `UCAL_BLESS=1`, not automatically. A baseline
  that rewrites itself records what happened; one that has to be asked records
  what was intended, and the diff is what a reviewer reads.

  Verified strict in all three directions: removing a field fails, changing its
  JSON kind fails, adding one passes.

  Its limit is stated in `STABILITY.md` rather than left for a green run to
  imply: a field that keeps its name and kind and starts reporting something
  *else* passes this, and is exactly the breakage the promise is about. Nothing
  mechanical reaches meaning.

## Fixed

- **The declared MSRV was false.** `rust-version = "1.85"`, and `bnum 0.14`
  requires 1.87 — so a caller on 1.85 could not build the **default**
  configuration at all. It had been wrong since `bnum` was updated, and nothing
  checked it, so nobody knew.

  Corrected to `1.87`, and CI now builds the workspace at exactly that version.
  The job pins the number as a literal rather than reading it from the manifest:
  a job that follows the manifest proves nothing about a manifest lowered by
  hand.

- **Three feature combinations were unsupported by accident.** `ucal-body`,
  `ucal-events` and `ucal-cosmo` on `u512` alone failed with twenty
  unresolved-`alloc` errors and no explanation. Each now says *this crate
  requires the `alloc` feature*, and says why: `ucal-core` is the crate that runs
  without an allocator, and nothing above it does.

- **Enabling both backends reported the wrong error first.** The guard fired,
  but `the name \`imp\` is defined multiple times` came before it — the error a
  caller reads and the one that says nothing. The `bigint` module is now gated on
  `not(u512)` so the guard's sentence is the only error.
