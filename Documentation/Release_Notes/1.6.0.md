# 1.6.0 — 2026-08-20

The mechanism without a wire.

1.5.0's last finding was a check that had been **correct and unrun in CI for four
releases**. This cycle asked how many others there were. The answer was fourteen,
plus a dispatcher defect that made every one of them conditional, plus a
third-party tool that runs on every push and does not catch what it is trusted
for.

None of it was findable by reading the claims, because every one of these checks
prints something that looks like work.

## The goal of this cycle: the mechanism without a wire

1.5.0 found five defects and four of them were the familiar shape — a claim with
no mechanism. The fifth was worse and is the one worth building a cycle on:

> `check-docs`' worked-examples check was **correct and unrun in CI for four
> releases.** It printed `--    worked examples not checked: target/release/ucal
> is absent` and moved on. Its own comment in `xtask/src/main.rs` warns that a
> check which silently skips is how a stale file survives.

A claim with no mechanism is findable by reading the claim. A **mechanism with no
wire** is not: the check exists, it is written correctly, it passes review, it
prints something on every run, and it is testing nothing. It came to light by
accident, because a frame committed into the documentation happened to make the
check fail locally in the one configuration where it had something to say.

That is the question for this cycle. **How many other checks are not connected to
anything, and how would anyone know?**

### Scope

**V1 — an audit of every check this project claims to run.** `xtask` has nine
`check-docs` checks, ten lints, a constants harness, a vector verifier and a
link checker; the workflows have four jobs across two files. (Written as "six
and twelve" when this scope was set, from memory. The audit counted them, which
is the smallest possible illustration of its own point.) For each: does CI
run it, does it run on the configuration that matters, and can it report success
without having examined anything?

The deliverable is a list, and the finding is whatever the list says. **Stop if**
the audit turns up more than can be honestly fixed in one cycle — then the
deliverable is the audit, and the fixes are scheduled.

**V2 — a check that no check can skip silently.** The specific mechanism, not the
general principle: every check reports `ok`, `FAIL`, or a *skip that fails CI*.
1.5.0's hole was a third state that looked like a pass. A skip is sometimes right
locally — the examples check genuinely cannot run without a binary — and never
right in CI.

**Stop if** it turns out some check must be allowed to skip in CI for a reason
that survives scrutiny. Then that reason is written down beside it, which is the
whole point.

**V3 — the argument-validation survey Z1.4 deferred.** `UCAL-E0001` is declared
as *malformed timestamp* and is what every CLI argument rejection in this binary
raises: `--color`, `--tick-sep`, and now `wallclock --once`'s frame size. That is
the D-A22 class, recorded in 1.5.0 and not fixed, because a fourth borrowed-code
correction in one cycle needed a survey rather than a spot fix.

This is the survey. One code for *an argument value is not valid*, a delta, and
every site moved onto it.

**Stop if** the survey finds the sites are not one class — if `--color bogus` and
a frame size out of range want different codes, that is a finding and the answer
is two codes with two reasons, not one code with a vague name.

### Done when

The audit exists, whatever it found is either fixed or scheduled with a reason,
and no check in this repository can report success without having run.

**V1 through V4 are done.** The audit found fourteen affected checks and one
dispatcher defect, all closed; the survey found argument validation spread across
two borrowed codes and moved seventeen sites onto one that names the condition;
V4 measured the distance between the declared frame and the bridge and recorded
it where a reader forms the belief it bounds.

## Added

- **`FRAME_BRIDGE_CLAIM`** (V4, D-A25). Rule F required a profile to declare its
  frame and never asked how far that is from the scale its bridge converts
  through. `UC-1` declares the CMB rest frame and bridges through TT, a clock on
  Earth's geoid; the gap is bounded at `5 × 10⁻⁶`, or 68 935 years over the datum
  span. Metadata only, inert like `BIG_BANG_CLAIM`, defaulted to zero so that
  adding it breaks no outside implementor. Printed by `ucal datum`.
- **`UCAL-E0018`**, *value not accepted for this option or field* (V3, D-A24).
  One code for four shapes with one remedy — a closed vocabulary missed, a shape
  constraint broken, a range left, a combination that cannot hold — from the
  command line and from data files alike.
- **A floor under every counted check** (V2). Each `check-docs` check is
  announced through one `report`, which fails below the smallest population it
  can be believed at. `xtask lint` reports `0 violations across 73 files` and
  refuses below 40. The constants harness refuses below 60 checks.

## Changed

- **An unrecognised `xtask` mode is an error** (exit 2) with the mode list
  printed, instead of falling through to the constants harness. The harness is
  now named `report`.
- **A skip is fatal in CI.** `check-docs`' worked-examples check may skip when
  the binary is absent locally; when `CI` is set, a skip is a failure.

## Fixed

- **Argument validation had no code and borrowed two that mean other things**
  (V3). `UCAL-E0001` is *malformed timestamp* and the CLI raised it twelve times,
  of which two were timestamps. `UCAL-E0060` is *body parameter missing required
  provenance* and was attached to a flag combination and to an arithmetic
  overflow. Seventeen sites moved; the overflows went to `UCAL-E0021`, which
  already meant exactly that.
- **Fourteen checks could report success having examined nothing** (V1, V2).
  Ten lints passed on a workspace that does not exist; three `check-docs` checks
  passed on an empty population; the constants harness met its exit criterion
  with zero checks.
- **Any typo'd `xtask` subcommand ran the constants harness and exited 0**, so a
  mistyped CI step was a green run of the wrong check.
- **`cargo semver-checks` does not catch a required method added to a public
  trait** (V1 Finding 6), which is the mechanism behind `STABILITY.md`'s promise
  that nothing which compiled stops compiling. Confirmed against 0.50.0 with a
  real external crate. `tests/compile_pass/profile_is_implementable.rs` is now a
  downstream implementor kept in the suite; it covers `Profile` and nothing else,
  and the rest of the public surface is still on the tool's word.
- **The wall clock's 22 tests had never run in CI** — built every time, run
  never, because `--workspace` cannot reach a file behind a non-default feature.

## What this cycle found out about itself

The premise was that a check reporting success without having examined anything
would be unusual. It was not. **Twenty-three named checks, fourteen with a
hole**, and every one of them previously unknown.

What made them invisible is uniform: each prints something that looks like work.
`ok    citations resolve against spec/ (0 distinct)` and `ok    citations resolve
against spec/ (124 distinct)` are the same sentence with a different number in
it, and nobody reads the number. That is why V2 is a floor and not a review — a
person sees a pass, a machine comparing `0` against `100` does not.

Three of the audit's own numbers had to be corrected after being recalled instead
of counted: the lints are ten and not twelve, the `check-docs` checks nine and
not six, and the lint walk reads 73 files and not the ~148 first written down. An
audit that miscounts its subject is not worth much, and the corrections are left
visible on the page.

**And the cycle committed its own defect while closing it.** The `-D warnings`
build printed `2`, and it was read past — `lint::run` had gone dead when the
caller switched to the population-returning version. CI caught it. Output that
looks like work, and nobody reads the count, in the commit that was fixing output
that looks like work.

## Carried forward from 1.5.0

- **The three asks in [`CONTACT.md`](../CONTACT.md)** are open, wanted, and a
  condition on nothing shipping.
- **The 2.0 bundle**, decided in `ROAD-TO-2.0.md` and not scheduled: withdraw
  `bigint` from the public feature surface, move the data model to `Cow`, give
  `Measured` a sign, and implement §15.1 in the library.
- **§15.1 is `UNIMPLEMENTED`** for `ucal-body` (D-A20). Both loaders — body files
  and, since 1.5.0, anchor files — live in the binary and say so.
- **`--all-features` cannot build this workspace**, because it enables both
  backends and the guard fires. Three tools now want something the feature
  surface cannot give them: `semver-checks` needs `--default-features`, the MSRV
  job needs `--features tui` spelled out, and this. It is item 1 of
  `ROAD-TO-2.0.md` and it is getting louder.
- **A rounded parameter is a different calendar.** 1.5.0 gave body files a
  `derived:` form for the case where the exact value cannot be written down; for
  every other parameter the last digit an author types still chooses their
  intercalation.
- **Ten of the twelve derived calendars have no anchor**, which is the ordinary
  case and not a gap, for the reason `D5-titan-anchor.md` established.
- **[`GE-U4-walk.sh`](../Proposals/GE-U4-walk.sh) is built and unrun.**
- **W3, a third locale**, postponed with its reason recorded.
- **The signing key has no authority behind it that is not the author**, and the
  release checksums are not signed.
- **Eight commits in the history are unsigned**, permanently.
