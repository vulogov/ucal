# 1.11.0 — UNRELEASED

In development on the `1.11.0` branch. `main` carries the released 1.10.0 line.

## The goal of this cycle: the standard that stops at the edge of one build

1.9.0's G2 found two global flags that were accepted and silently did nothing,
and named the shape: **a standard applied in one place and not the one beside
it.** 1.10.0 then hit it twice more without meaning to.

This cycle is that shape, looked for on purpose.

### The two known instances

**`-D warnings` reaches one workflow and not the other.** `verify.yml` sets it
across the workspace and all targets. `features.yml` builds **twenty-three
feature combinations** and does not, and they are not clean:

```
u512,std          8 warnings
u512,std,events   7 warnings
u512,std,civil    3 warnings
u512,tui          3 warnings
```

Every one is an unused import or an item that is never constructed — which is to
say **a missing `#[cfg]`**. That is precisely the defect class `features.yml`
exists to catch, and it has caught five of them by build *failure* while letting
this class through as a warning nobody reads. 1.10.0 added a sixth by inserting a
function above `anchorless_note` and taking its `#[cfg(feature = "body")]`; the
build broke, so it was found. Had it merely warned, it would not have been.

**One generated artefact no longer generates.** `schema.rs` states the principle
about its own file — *a generated artefact that is committed must be regenerable,
or it is a copy that has started to drift*. Measured across the four generators:

| generator | regenerating changes |
|---|---|
| `gen-docs`, `gen-examples`, `gen-schema` | checked by `check-docs`, clean |
| `gen-rules.py` | none |
| **`gen-diagnostics.py`** | **7 insertions, 20 deletions** |

Its own header says it exists because *"a hand-copied list of error codes drifts
silently"*. Running it while adding `UCAL-E0019` deleted a hand-written paragraph
about exits 1 and 70 and downgraded every chapter cross-reference. The file has
been edited by hand since it was last generated, so the generator is now the
thing that would introduce the drift.

### Scope

**P1 — `-D warnings` on every combination the features workflow builds.** Set it
in `features.yml`, then fix what it surfaces. The fixes are `#[cfg]` attributes,
not suppressions: an item that exists only under some features should say so.

**Stop if** a warning cannot be fixed without gating something that ought to be
unconditional. Then the finding is that the feature graph and the code disagree
about what is optional, which is worth more than a clean build.

**P2 — every generated artefact regenerates, or is not called generated.** One
does not. The repair is a decision rather than a patch: teach `gen-diagnostics.py`
the hand-written parts, or declare the appendix hand-kept and delete the
generator. Both are honest; leaving a generator that destroys content is not.

**Stop if** teaching the generator means teaching it prose. Then the answer is
the second option, and the reason is recorded where the generator used to be.

**P3 — the audit: what else runs in one place and not the one beside it?**
[`V1`](../Proposals/V1-check-audit.md) asked this of every `check-docs` check and
found fourteen that could report success having examined nothing. The same
question has never been asked of the **CI jobs**, the **generators**, or the
lints — and 1.10.0 needed a presence filter in two surface suites for exactly
this reason, because a baseline blessed under `--features full` is checked under
the default ones.

**Stop if** the audit finds nothing. That is a publishable result and the reason
V1 was worth doing.

### Done when

Every standard this repository applies is applied everywhere it claims to apply,
or the release notes name the exception and why it stands.

**All three landed.** P1 put `-D warnings` on the twenty-three combinations and
gated six items that existed under some features without saying so. P2 taught the
one generator that had drifted and made both of them checked, which is

## Added

- **`ucal add`** — an instant, moved by a whole number of a chosen unit.

  **The operation this program did not have.** It could *read* time — `now`,
  `to-civil`, `cal from` — and *measure* it — `between`, `explain` — and not move
  through it. `seq` walks between two instants and needs both; `between` measures
  a span whose ends you already hold. There was no way to say *this instant, plus
  one Martian year*.

  ```
  ucal add <T> 1   --step mars-d-year
  ucal add <T> -3  --step T1
  ucal add <T> 100 --step mars-d | ucal cal show mars-d -
  ```

  **Unsigned time is the whole design here.** `N` is signed and the result is
  not: absolute time is unsigned (Rule B) and a tick count cannot be negative, so
  moving below the datum is **`UCAL-E0020`** — *result precedes the datum*, the
  code **named for this operation**, which no raiser had ever produced for it.
  Past the ceiling is `UCAL-E0021`. Rule O forbids wrapping and saturating, so
  neither is clamped, and a test injects the clamp to prove the refusal is real.

  Exact: `N × unit` in integer ticks, on the vocabulary `seq --step` already
  parsed. Two properties are tested — moving out and back returns exactly where
  it started, and the span it opens measures back to the same count with **no**
  remainder.
- **`between --at` takes a calendar's own unit**, not only a tier. *How many
  Martian days is that?* The flag has always meant *express this span in this
  unit*; it now reads the same vocabulary `add` and `seq` do.

  **One flag widened rather than a second flag added.** A second meaning the same
  thing in a different vocabulary is how two spellings of one question come to
  disagree — the reason `cal show` did not grow `cal derive`'s options in 1.9.0.

  `at.tier` is still emitted for a tier and is **absent** for a calendar's own,
  because it is a path in `ucal-json/1` and removing one is breaking — and
  because a field named `tier` should not name a Martian day. `at.unit` is the
  new one and names either.

## Fixed

- **`-D warnings` now reaches every combination the features workflow builds**
  (P1), and six items that existed under some features without saying so are
  gated.

  The two workflows exist to catch the same defect — a `#[cfg]` that does not
  match what the code needs — and `features.yml` had caught six of them by build
  *failure* while letting the identical defect through as a warning nobody read.

  What it was hiding, once each layer stopped masking the next:

  | item | exists when |
  |---|---|
  | `RatInterval` | `cosmo` — it is `parse_redshift`'s return type and nothing else's |
  | `qualified::Kind` | `civil` — read once, by `to-civil` |
  | `years_quantity` | `any(events, cosmo)` — a window's width, or an enclosure's ends |
  | `Rounding` | `civil` — `to-civil`'s default when `--round` is absent |
  | `parse_form`, `codec::Form` | `civil` **and** `std` — `run_now`'s, and nothing else's |

  Every fix is an attribute, not a suppression. `years_quantity` is the one worth
  looking at: it needed `any(events, cosmo)`, which is a shape no single feature
  name could have expressed, and it is why the item had no attribute rather than
  a wrong one.

  **The five libraries were already clean.** All of it was in the binary crate,
  in eight of the nineteen builds — and it surfaced one layer at a time, because
  a lib that fails to compile never lets the binary's own warnings appear.

  The `refused` job inherits the flag too, and its checks still hold: the
  backend guard is still the **first** error line, which is the property that job
  exists to defend and the one `-D warnings` could most easily have broken by
  promoting a warning ahead of it.

- **The audit found three more** (P3), and its stop condition — *finding nothing
  is a publishable result* — did not fire.

  V1 asked of every `check-docs` check whether it could report success having
  examined nothing, and found fourteen that could. The same question had never
  been asked of the **CI jobs**, the **generators** or the **lints**.

  **`release.yml` set no `-D warnings`, and it is the only workflow that compiles
  for anything but the host.** Five targets, including `x86_64-pc-windows-msvc`
  and both aarch64 musl — so a warning firing only on one of those was invisible
  everywhere, in the builds that produce the binaries a downloader actually runs.
  Cargo caps lints on registry dependencies, so this is about this workspace's
  own code and cannot be tripped by somebody else's crate.

  **`features.yml` built without `--locked`** while `verify.yml` and
  `release.yml` used it — so the workflow that exists to prove twenty-three
  combinations build could have proved it against a different dependency
  resolution than the one being shipped. All twenty-three now pass with both
  `--locked` and `-D warnings`, and the `refused` job's guard is still the first
  error line.

  **`xtask` is outside the lint, and nothing said so.** `lint::run` scopes to
  `crates/`, so an injected float in `xtask/src` produced no violation while the
  count still read *84 files* without naming the tree. The walker beside it
  documents why it skips `target`, `.git` and the trybuild fixtures; this
  documented nothing.

  **The exclusion is right and the silence was not.** These rules are about
  *shipped* code in their own wording — Rule E forbids a float "anywhere in a
  shipped crate", §19.5's no-panic rule is about the CLI crate — and `xtask` is
  `publish = false`, renders human-readable scales in floating point on purpose,
  and panics freely because a failed build tool should stop. So the reason is
  recorded where the scoping happens, and the output now reads
  `UC lint — <root>/crates`.
- **The book's generated appendices are checked, and one had drifted** (P2).
  `check-docs` has a tenth check.

  `schema.rs` states the rule about its own artefact — *a generated artefact that
  is committed must be regenerable, or it is a copy that has started to drift.*
  `docs/TIERS.md`, the worked examples and the JSON schema were all held to it.
  **The book's generators were not**, and `gen-diagnostics.py` had drifted twenty
  lines: run while adding `UCAL-E0019` it deleted a hand-written paragraph about
  exits 1 and 70 and downgraded every chapter cross-reference to an em dash. A
  generator written so that *"a hand-copied list of error codes drifts silently"*
  could not happen had become the thing that would introduce the drift.

  **P2's stop condition did not fire.** It said to stop if teaching the generator
  meant teaching it prose — but it already emits prose in three places, so the
  paragraph is a constant beside them, and the rest was two hand-maintained
  tables not updated since `E0014`.

  The check snapshots the chapters, runs each generator and compares, restoring
  the tree before reporting: a check that leaves its own damage behind passes on
  the second run having compared its own output. A missing `python3` is a failure
  rather than a skip, so a green run cannot mean *the interpreter was absent*.
  Verified strict by hand-editing a generated chapter and watching it refuse.

  The first version parsed `OUT =` from each script to find what it writes, and
  `gen-rules.py` has no such variable — it writes two files inline. A check that
  assumes how a script is written checks only the scripts written that way.

## Carried forward from 1.10.0

- **`UCAL-W0003` reaches a reader**, after being a `MUST` the code produced and
  discarded. Five rendering paths carry it; an ordinary date still says nothing.
- **Every parameter of a derived calendar is read at the epoch**, so the solar
  day no longer drifts while the leap rule stays frozen. No shipped parameter
  declares a rate, so this changes no number today — it settles which number it
  would have been.
- **Derived calendars invert.** `cal from` is the flagship, and the answer is a
  window because a local day is a span and the anchor's uncertainty propagates.
- **Obliquity is reported and not consumed**, with the reason: the stored angle
  gives a season's amplitude and not its phase, and a phase is empirical
  (Rule J.3).
- **Two of fifteen calendars have an anchor.** That is the ceiling on local
  fields, on `--clock-local`, and now on `cal from` as well. D5 recorded what
  establishing a third honestly costs.
- **Fifteen calendars rest on nineteen distinct published figures**, of which
  fourteen decide a leap rule outright — one of them, Jupiter's year, deciding
  five calendars at once.
- **§15.1 is `UNIMPLEMENTED`** for `ucal-body` (D-A20), and an arena for the
  library's loader is still the path nobody has costed.
- **`cargo semver-checks` has one known blind spot**, covered by four
  compile-pass fixtures; six further categories were probed in A3.
- **1.9.0 is the first release whose binaries a downloader can check end to
  end.** Releases before it are unsigned and will not be signed retrospectively.
- **The signing key has no authority behind it that is not the author.**
- **The three asks in [`CONTACT.md`](../CONTACT.md)** are open, wanted, and a
  condition on nothing shipping.
- **[`GE-U4-walk.sh`](../Proposals/GE-U4-walk.sh) is built, run, and waiting on
  two readers.**
