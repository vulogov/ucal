# 0.9.0 — UNRELEASED

In development on the `0.9.0` branch. `main` carries the released 0.8.0 line.

## The goal of this cycle: hold still

**A release whose product is an empty `Breaking` section.**

This cycle was added during 0.7.0, when the plan was found to contradict its own
exit criteria. They require **two consecutive releases with no breaking change**;
the five cycles as first written supplied at most one, since 0.8.0 is defined as
the cycle that spends the breaks. A gate that cannot be met is a gate that gets
waived, so 0.9.0 exists to make it meetable.

There is nothing to build here, and that is not a gap in the plan. **A cycle
whose diff contains no `Breaking` section is evidence that the surface has
stopped moving**, and that evidence cannot be manufactured faster by working
harder. It is exactly the kind of claim this project insists must have a
mechanism, and the mechanism is elapsed time.

### What may happen

Bug fixes. Documentation. Performance. Fields added to `#[non_exhaustive]`
records where something turns out to be missing. Corrections to claims that
turn out to be false — every cycle so far has found several, and there is no
reason to think this one will not.

### What may not

Anything that changes a name, a shape, a meaning or a default. And **no new
commands or crates**, which is the rule 0.8.0 was closed early to respect: 1.0
freezes an addition whether or not it broke anything, and one made here would
arrive frozen with a single cycle of settling and nobody's use behind it.

Three things were dropped from 0.8.0 under that rule and are named in its notes
so the cost is visible: shell completions, a generated man page, and a published
JSON Schema for `ucal-json/1`. Under this rule they wait for 2.0.

### Done when

0.9.0 has shipped with an empty `Breaking` section, and nothing found since
0.8.0 is waiting for a breaking change to fix.

**A criterion that is already met, and should not count.** 0.7.0 and 0.8.0 both
shipped with an empty `Breaking` section, so *two consecutive releases with no
breaking change* is satisfied on a literal reading and 1.0 is one release away.
It should not count, for the same reason the contact gate is open: both were
quiet because **nobody outside this repository has used the API**, so nothing
pushed back on it. A counter of quiet releases measures attention, not
stability. Recorded in [`ROAD-TO-1.0.md`](../Proposals/ROAD-TO-1.0.md) and
[`STABILITY.md`](../STABILITY.md) rather than walked through.

**If something is waiting, it is spent here and the counter restarts.** That
costs one cycle and is the whole reason the counter is two rather than one — a
single quiet release proves only that nobody looked.

### And the gate that is still open

**Contact has not happened.** C1, C2 and C3 in
[`CONTACT.md`](../CONTACT.md) all need someone who is not the author, and two
cycles have now passed without one. The gate is a condition on **1.0**, it does
not expire, and it is not a reason to stop releasing — but it is the reason 1.0
may not ship at all, and `0.x` forever is an honest resting state.

The cheapest of the three is thirty minutes in any language, with nothing to
install. Since 0.8.0 the binary itself will print the expected values:
`ucal verify`.

## Breaking

**This cycle stopped being the quiet one, deliberately.** An audit for objections
to 1.0 found three, and the first cannot be fixed without a break — so it was
taken here, where it still costs nothing, rather than left to be frozen.

- **`ucal_core::Ticks` is a newtype, not a re-export of the backend integer.**
  It was `pub type Ticks = bnum::types::U512`, so 24 public functions were
  publishing a third-party type.

  Two things would have been frozen by 1.0. **The crate would have been married
  to one version of `bnum` for the whole of `1.x`** — a `bnum` major release
  changes `U512`, which changes this crate's public API, so the choice of
  integer library, an implementation detail by every other measure, becomes a
  compatibility commitment. And **the type's identity changed with a feature**:
  `bnum::types::U512` under `u512`, `num_bigint::BigUint` under `bigint`, so a
  downstream crate naming the concrete type in *its* API had a signature that
  changed shape with a feature it did not control.

  `Ticks` is now `#[repr(transparent)]` over the backend value and forwards
  `TickInt`. What to write instead: `<Ticks as TickInt>::zero()` for
  `Ticks::from(false)` or `U512::MIN`, and `Ticks::ZERO` in a `const` on the
  default backend. Nothing else changes — the arithmetic surface was already
  `TickInt` and stays exactly as it was.

  **What this does not fix**, and it is the harder half: `u512` and `bigint`
  remain mutually exclusive, so two libraries that each chose a backend still
  cannot appear in one dependency graph. Demonstrated rather than asserted —
  two crates, one choosing each, and the build of anything depending on both
  fails with the guard's own message. Neither library author can fix it; only
  the end user can, by making one of them change. That is a design question and
  is recorded in [`STABILITY.md`](../STABILITY.md) rather than papered over.

## Added

- **A panic handler in the binary.** A panic used to leave through Rust's
  default hook: `thread 'main' panicked at …`, a suggestion to set
  `RUST_BACKTRACE`, and exit **101** — a message addressed to the person who
  wrote the program shown to the person running it, and a status §19.5 does not
  define, so a script could not tell "your input was wrong" from "the program
  broke".

  Now: what happened, where, the fact that **the input was not at fault**, the
  issue tracker, and exit **70** (`EX_SOFTWARE`, outside §19.5's 0–9 on purpose
  so it cannot be confused with a diagnosed failure). The source location is
  kept — it is the one part of the default output worth having, and a bug report
  without it is worth much less.

- **`no-panic-in-cli` lint.** `.unwrap()`, `.expect(`, `panic!`, `unreachable!`,
  `todo!`, `unimplemented!` and `assert!` are refused in `crates/ucal/src`. The
  library crates beneath are exempt on purpose: an `expect` on an invariant just
  established — `self >= other` immediately after comparing — is the right code
  there, and rewriting it into `Result` would trade a provably-unreachable
  branch for an error case every caller must handle and none can trigger. What
  must not happen is a panic in the crate that turns a typo into a backtrace.

  Writing it turned up a weakness in the existing `shipped_extent` helper, which
  answers "where does test code start" with a single cut point and degrades to
  "scan everything" for a file with a `pub` item after its tests —
  `crates/ucal/src/table.rs` is exactly that, and the lint reported five hundred
  `assert!`s in its test module. Replaced with a brace-matching
  `test_module_ranges`.

  Four sites survive as declared exemptions, each dividing by a profile constant
  that is structurally non-zero. The alternative — `Result` through twenty-three
  call sites, most inside a `Value::Section` literal — buys nothing, and the
  fallback that would avoid both is worse than either: substituting a value for
  a zero denominator prints a *wrong number* where this prints nothing, and this
  project would rather stop than answer incorrectly.

- **`hostile_input.rs` and `panic_handler.rs`.** Forty malformed invocations of
  the real binary, asserting that none panics, that each exits non-zero with a
  sentence on stderr and nothing on stdout, and that the codes come from §19.5's
  table. Plus an induced panic — via `UCAL_PANIC_SELFTEST`, an environment
  variable so it is not CLI surface — checking the handler rather than reading
  it.

  Not a fuzzer, and the module says so: this finds the class of defect that
  reached 0.9.0 and would not find a rare arithmetic edge.

## Changed

- **The documentation was brought to the state of the tree**, which turned up
  the cycle's largest finding — see `Fixed`.

  The book: seven derived calendars where it said three, seven bodies where it
  said "Earth, Mars and Titan", 518 tests where it said 381, and a pinned commit
  five weeks and thirty-seven test-suites out of date. `PINNED.md` is the book's
  authority declaration under Rule S, so a stale one makes every claim in the
  book checkable against the wrong tree.

  Chapter 15's derivation table gained the four new bodies with their days-per-
  year computed rather than quoted — Mercury's is `0.499990`, not `0.5`, and the
  chapter now says why that near-half is the 3:2 spin–orbit resonance arriving
  in a column not built to display resonances. Chapter 8 gained the observation
  that five of seven calendars having no anchor is the *ordinary case* and not
  five failures beside two successes.

  Appendix C gained `UCAL-E0014` and exit `70`. `STABILITY.md` gained the sixth
  promise — the command line never aborts — with its mechanisms and its limits.
  `CONTACT.md` now points at `ucal verify`, and says in the same breath that a
  self-check agreeing with itself is not the confirmation C1 asks for.

- **`--sep` works.** It was declared, documented as *"must not be a digit
  (§6.3)"*, and **never read** — so `--sep 1` was accepted in violation of its
  own help text, and `--sep _` changed nothing while appearing to succeed. It is
  now validated and applied, in text and in `--json`.

  Applied at render time through a new `Render::form_sep` rather than threaded
  into every `cmd_*` signature, which would have been a breaking change to the
  library. `Render` is `#[non_exhaustive]` precisely so a rendering option can
  arrive without one — the 0.6.0 decision paying for itself in the cycle that
  cannot afford a break.

## Fixed

- **`UCAL-E0011` was reported for a condition it does not describe.** Rule N
  pins E0011 to a name *collision*; a lookup *miss* had no code, so an unknown
  tier name produced

  ```
  UCAL-E0011: duplicate name in the active locale table (unknown tier name; …)
  ```

  — a canonical meaning that is the opposite of the context beside it. A reader
  looking E0011 up in Appendix E would have found a description of something
  that had not happened.

  `UCAL-E0014`, *name not found in the active locale table*, is added as
  [D-A17](../../spec/SPEC-DELTAS.md); E0011 keeps Rule N's meaning exactly.
  `Code` is `#[non_exhaustive]`, so no exhaustive match breaks.

- **`ucal show` exited 0 when every requested calendar failed.** A script asking
  for a calendar that does not exist got a success and a table of dashes. It now
  exits 7 with a message naming `cal list`. A *partial* failure still exits 0
  deliberately: the output is useful and the per-row `error` is visible, and
  turning the default invocation non-zero the moment one body lacks an anchor
  would make the ordinary case look broken.

- **`ucal cal anchor <unknown>` answered confidently about a calendar that does
  not exist.** It reported `anchor: none` and exited 0, which reads as "this
  calendar exists and its phase is undetermined" rather than "there is no such
  calendar". The two are different answers and now have different outcomes.

- **Two spec deltas were recorded and never applied.** `spec/UCAL-1.1.md` is the
  normative text and its own header says it is "RFC UCAL-1 with the standing
  deltas applied in place", each amended passage marked inline. **D-A16 and
  D-A17 were not there.**

  D-A16 was written in 0.4.0 and struck the words *"always prints the SI
  equivalent alongside"* from §4.3 — the whole point of the `--bridge` work. Two
  releases later the normative specification still said "always", contradicting
  the implementation, the release notes and `STABILITY.md` at once. A conforming
  implementer reading the normative text would have built the behaviour the
  project spent a cycle removing.

  Both are now applied and marked. The header's count went from fourteen
  standing deltas to sixteen, and the class table from three amendments to five.

  *This is the pattern again, in the one document where it costs most.* The
  delta was reasoned, recorded, published — and the normative text was never
  edited, because nothing checked. `check-docs` now fails if a standing delta is
  not marked inline in `UCAL-1.1.md`, and if the header's count disagrees with
  the number of them. Verified strict against both: an unmarked delta and a
  wrong count.

- **`Value::rendered_text` had a catch-all arm** — carried over from 0.8.0's
  `Bool` fix; the `--sep` work made the remaining `Bridge` case explicit rather
  than implicit.

## Carried forward from 0.8.0

- **The contact gate is open**, and it is the only thing between this project and
  a 1.0 it would be honest to ship.
- **Three additions were dropped** and now wait for 2.0: shell completions, a
  man page, a published JSON Schema. Recorded because the trade may prove wrong,
  and it will show as a stranger unable to tab-complete a binary that promises
  to be easy to try.
- **The signing key still has no authority behind it that is not the author.**
  It now travels in the `ucal` and `ucal-core` package tarballs on crates.io,
  which cannot be edited after publication, so a change here is detectable —
  but first contact remains trust on first use.
- **Titan has no anchor**, and after 0.7.0's search the reason is specific: the
  IAU publishes the rotational elements, nobody publishes a mean-solar-time
  convention, and deriving one needs an ephemeris this project does not carry.
  The same is true of the four bodies added in 0.8.0.
- **`Measured` cannot express a retrograde rotation.** Venus is stored as a
  magnitude with the sign in a comment. Fixing it is a breaking change to a
  published type that buys one fact about one body.
- **[`GE-U4-walk.sh`](../Proposals/GE-U4-walk.sh) is built and unrun.**
- **Eight commits in the history are unsigned**, permanently.
