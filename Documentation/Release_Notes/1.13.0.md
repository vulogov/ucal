# 1.13.0 — UNRELEASED

In development on the `1.13.0` branch. `main` carries the released 1.12.0 line.

## The goal of this cycle: the mechanism is built and the data is not

This project has found the same shape in its own work six times, and given it a
name each time: a claim with no mechanism, a mechanism with no wire, a schedule
with no date, a procedure whose steps undo each other, a requirement with no
wire, a standard that stops at the edge of one build, and — last cycle — a claim
about the world nobody asked the world about.

**This one is the mirror image of all of them: a mechanism with no data.**

### Counted, before it is claimed

| mechanism | shipped data |
|---|---|
| derived calendars | 15, of which **2** have the anchor a local date needs |
| bodies | 16 |
| events | 22, **every one in the past** |
| **ephemerides** | **0** |
| **black holes** | **0** |
| **stellar timelines** | **0** |

Four of those numbers are zero and one is 2/15, and **they are all zero for the
same reason**: this project will only ship a figure it can quote verbatim from a
source it can cite, and nobody has done the quoting.

That is not a defect. [`D5`](../Proposals/D5-titan-anchor.md) concluded that *no
anchor* was the honest answer for Titan, and 1.12.0 shipped an ephemeris format
with no ephemerides for exactly the reason `cal validate` found in this project's
own `europa.hjson` — a figure typed from memory, citing NASA for a solar day NASA
does not publish, wrong in the third decimal, deriving a different calendar.

**But it has become the dominant fact about this project, and nothing measures it
or says it out loud.** A reader meets a program with an ephemeris command and
discovers by trying that there is nothing to run it against. `ucal timeline`
calls itself *the whole of time* and covers ten of the hundred and three
cosmological decades [`S2`](../Proposals/S2-deep-time.md) measured, all of them
behind us.

### Scope

**T1 — the emptiness is measured, and said.** A report that counts every shipped
mechanism against the data behind it, so `0 ephemerides` is a number this project
states rather than one a reader discovers. And a command whose catalogue is empty
should say it is empty, rather than failing in a way that reads as a defect in
the program.

**Stop if** the count comes back full — if every mechanism turns out to have data
and the table above is wrong. Then the finding is that I miscounted, which is
worth more than the feature.

**T2 — an ephemeris file is validated to the same standard as a body file.**
`cal validate` loads a §15.1 file, checks it, and runs a **precision probe**:
move the last published digit of each figure, re-derive, and report whether the
calendar changes. An ephemeris file gets no such check, and the probe is *more*
apt there than it was for bodies — move the last digit of `P` and see how far the
prediction at cycle 5000 moves. It would say, immediately, *your quoted σ_P is
smaller than the precision you quoted `P` to*, which is a real error and a common
one.

**Stop if** the probe's answer is always swamped by `σ_P` — if the quoted
uncertainty already dominates the last-digit question at every cycle. Then the
finding is that a published σ subsumes the probe for ephemerides, which is worth
recording and would be a genuine difference from bodies, where no σ is published
at all.

**T3 — the oldest carried caveat, attempted honestly.** *Two of fifteen
calendars have an anchor* has appeared in every release note for many cycles as a
limitation and never as a task. Thirteen derived calendars are complete in units,
intercalation and cycles, and cannot produce a local date. `D5` recorded what
establishing one costs for Titan and concluded it could not be done honestly
there.

The question this cycle asks is narrower and has not been asked: **is there a
class of body for which an anchor is cheap and citable?** A tidally locked moon's
rotation is its orbit, and its phase may be fixed by a published epoch of a
transit or an eclipse rather than by an observation somebody has to make.

**Stop if** the answer is no for every class. Then the honest outcome is D5's,
generalised: the caveat is permanent, it goes in the specification rather than in
a release note, and it stops being carried forward as though somebody were
working on it.

### Done when

Every shipped mechanism either has data behind it, or the project states how much
it has and why that is the honest number.

### Explicitly not in scope

- **Anything breaking.** `cargo semver-checks` runs against the published 1.12.0.
- **Inventing a figure to fill a table.** The whole point. A fabricated
  ephemeris, mass or anchor would be worse than an empty catalogue, and the
  emptiness is the thing being measured rather than the thing being fixed.
- **Ephemeris evaluation, and fitting anything.** `S1`'s boundary and `S3`'s,
  unchanged.
- **A frame for `UC-1`**, and **`H1`'s fourth finding**. Both 2.0.
- **`S3`'s C — certified Kepler.** Still conditional on a caller, and there is
  still no caller.
- **W3, the third locale**, still waiting on a choice of language.

## Carried forward from 1.12.0

- **1.12.0 published from the merge commit**, so `.cargo_vcs_info.json` names the
  commit its tag sits on and `verify-release` compares cleanly. 1.11.0 published
  from the cut commit and cannot be repaired; the procedure now says to merge
  first, and this is the first release where it did.
- **`cargo package` is not reproducible for this workspace** once a later
  compatible version is published, because packaging resolves an intra-workspace
  dependency against the registry rather than the path. 1.9.0 measured
  byte-reproducibility correctly and nobody stated its shelf life.
- **The signing key was rotated on 2026-08-31** and nothing signs the new one,
  because the key that could have is the one whose passphrase was lost. Every
  crate published at 1.11.0 or earlier carries the retired key immutably, so a
  reader comparing this repository against an older crates.io version finds them
  disagreeing for that reason.
- **v1.9.0 is unsigned, permanently.** `sign-release` existed and was never run
  for that tag, so **v1.11.0 is the first signed release** — and signing v1.9.0
  now would say a 2026-08-31 key vouched for a 2026-08-27 artefact.
- **`TDB` is a bound and `TCG`/`TCB` are exact**, because two of the three
  offsets are defining constants and one is a series.
- **A light-year is a time unit wearing a distance's clothes**; a parsec cannot
  convert exactly, for a reason about its definition.
- **`ephem` reports and does not fit.** A quadratic trend in `O − C` is `Ṗ`.
- **`ucal` is a coordinate clock in one frame**, which nothing said until black
  holes made it matter.
- **§15.1 is `UNIMPLEMENTED`** for `ucal-body` (D-A20).
- **The three asks in [`CONTACT.md`](../CONTACT.md)** are open and wanted.
- **Eight commits in the history are unsigned**, permanently.
