# 0.8.0 — UNRELEASED

In development on the `0.8.0` branch. `main` carries the released 0.7.0 line.

## The goal of this cycle: the last breaking window, and the last additions

Two halves, and the second was added during 0.7.0.

### B — whatever contact found

Nothing invented here. This half exists so that 0.7.0's findings do not have to
wait for 2.0, and it is why 0.8.0 is allowed a `Breaking` section when 0.9.0 is
not.

**As this cycle opens, that half is empty.** 0.7.0 shipped with its contact gate
still open — C1, C2 and C3 all need someone who is not the author, and nobody
has arrived. If they arrive during this cycle, whatever they find lands here.
If they do not, this half stays empty and that is recorded rather than
reinterpreted.

### A — the additions, and why they are here rather than in 0.9.0

An additive feature is not free because it breaks nothing. **1.0 freezes it
either way**, so a command added in 0.9.0 reaches 1.0 with one cycle of settling
and nobody's use behind it — and 0.9.0's only evidential product is that the
surface stopped moving. Adding surface during it undercuts the one thing that
cycle exists to demonstrate.

So the additions land here, where a mistake made in adding them can still be
corrected in the same cycle by the breaking half. This is the last release that
can do that.

**A1 — `ucal between <a> <b>`, the missing verb.**

The project's central claim is that a duration belongs on the tier ladder, and
no command puts one there. `explain` describes a point; `ruler` marks a span
without measuring it. The arithmetic already exists and is unreachable from the
binary: `Instant::since`, `Instant::between`, `Delta::in_tier`, `Delta::divmod`,
`Delta::tier_of`.

The delta in ticks, its base-5 group decomposition, its natural tier, its
`divmod` against a named tier, and SI only behind `--bridge`. A `Signed` result
when the order is reversed — `between` already returns one, and swallowing the
sign is the kind of convenience Rule Q exists to refuse.

**A2 — `ucal verify`, the self-check inside the shipped binary.**

Re-deriving the constants needs the repository and `xtask`. Someone who typed
`cargo install ucal` cannot check that the binary they are holding reproduces
the published values, and the first question an external implementer asks is
*what should I get* — to which the answer is currently "clone a repository
first".

The one item aimed at C1 rather than at a user. If contact is the gate 1.0
cannot pass, then lowering the cost of the ask is the only work that moves the
gate from inside this repository.

**A3 — more bodies.**

The mechanism is body-independent and ships Earth, Mars, Saturn and Titan, which
makes a project whose central argument is anti-Earth-centric look Earth-centric
in its own `cal list`.

**Most candidates will land exactly where Titan is** — complete in units,
intercalation and cycles, incomplete in phase — and that is the result rather
than a shortfall. A body without an anchor is the ordinary case; Earth and Mars
are the exceptions, and a table where the exceptions outnumber the rule
misrepresents which is which.

Every parameter cited, and **no anchor invented so that a calendar renders**.
D5's search in 0.7.0 is the template for how much a phase citation costs to
establish, and the answer for most of these will be the same one it found for
Titan: the rotational elements are published, the solar-time convention is not.

### Done when

Every finding from 0.7.0 that needs a breaking change has had one, A1–A3 have
landed or been recorded as dropped with a reason, and nothing is left waiting
for the next window.

0.8.0 itself *may have* a `Breaking` section — that is what it is for. The
release that must not is 0.9.0.

### Explicitly not in scope

- **Anything needing a closed vocabulary to gain a variant** — a new `Form`, a
  fifth `Rounding`, another `Scale` or `CivilCalendar`. Those read as additions
  and are breaking changes to every exhaustive match, which is the property
  `CLOSED_VOCABULARIES` records. Check it before designing a feature, not after.
- **Shipping 1.0.** The contact gate is a condition on the version number and
  does not expire. If it is still open at 0.9.0, 1.0 waits.

## Added

- **`ucal between <from> <to>` (A1)** — how far apart two instants are, stated
  on the tier ladder.

  Every other command answers *what is this instant*. None answered *how far
  apart*, which is the operation the grid exists for: a duration's natural home
  is a ratio between rungs, not a count of somebody's seconds. `explain`
  describes a point; `ruler` marks a span without measuring it. The arithmetic —
  `Instant::since`, `Instant::between`, `Delta::in_tier`, `Delta::divmod`,
  `Delta::tier_of` — has been in `ucal-core` the whole time and was unreachable
  from the binary.

  ```
  ucal between <FROM> <TO> [--at <TIER>]
  ```

  | field | |
  |---|---|
  | `direction` | which way round, in words |
  | `ticks` | the difference, exactly |
  | `natural_tier` | the coarsest rung of the 45 that fits inside it |
  | `on_the_ladder.<tier>` | decomposed across the named tiers, reassembling exactly |
  | `at.*` | with `--at`: the divmod at one named tier |
  | `si_bridge.seconds` | with `--bridge` only |

  **The sign is reported, never absorbed.** `Instant::between` returns a
  `Signed` because the domain is unsigned (Rule Z) and a difference need not be.
  Quietly taking the magnitude would make `between a b` and `between b a` print
  the same document, which is the convenience Rule Q refuses — so the test is
  that they differ.

  **Leading zeros are dropped; interior zeros are kept.** A leading zero says
  "nothing this coarse", which `natural_tier` already says once. An interior
  zero is a digit of the answer, and dropping it makes the rows unreassemblable.

  **The decomposition stops at the tick and is still exact.** The named tiers
  are not contiguous — there is a gap between `spark` (`5^45`) and `tick` (one)
  — so everything below one spark lands whole in the tick row. A `0` there means
  the difference is exactly representable at spark granularity.

  **No SI unless asked.** A second is an Earth unit and the interval between two
  absolute instants is not an Earth quantity (Rule A.5, D-A16). `--bridge`
  converts on request, through `Value::quantity`, so the rounding is declared
  and appears in the certification block.

  Five tests in `between.rs`, on top of the six invariant suites that pick the
  command up automatically. The one that matters is that the ladder reassembles
  to the difference exactly — a decomposition that renders beautifully and adds
  up to the wrong number is the failure a rendering test cannot see. Verified
  strict against two injected defects: dropping interior zeros, and swallowing
  the sign.

  Fourteen new `ucal-json/1` paths, all additions, which the baseline permits
  without a major bump — and it refused to pass until blessed, which is the
  asymmetry working.

- **`ucal verify` (A2)** — re-derive the declared constants and check that this
  build reproduces them.

  Re-deriving them otherwise needs the repository and `xtask`, and `xtask` is
  `publish = false`. Someone who typed `cargo install ucal` could not check that
  their binary agreed with the published values, and the first question an
  external implementer asks is *what should I get* — to which the answer was
  "clone a repository first". **This is the one item aimed at C1 rather than at
  a user.**

  Three constants, each re-derived rather than read back: `BEAT` as `5^60` by
  repeated multiplication, `SECOND` as `18548584399861 × 10^30`, and
  `ORIGIN_OFFSET` by re-executing §2.2's provenance chain **from the record's
  own published input** — `13.787` Gyr parsed as an exact integer, never a
  float — rather than from a copy of the answer. Plus three structural
  invariants: the datum is a whole number of beats (§2.4), `5^divisibility`
  divides `SECOND` exactly and `5^(divisibility+1)` does not (D-3), and all 45
  rungs recompute as `5^(60+5k)`.

  **The output states what a green run does not establish**, because a
  self-check is exactly the kind of thing a reader promotes into "verified" —
  at which point the command would be arguing against C1 instead of for it.
  Every number is computed by one implementation from one specification;
  agreement means the arithmetic works and reproduces `fixtures/vectors.json`,
  not that the specification is right. That disclaimer is load-bearing, so
  there is a test that it is present.

  What it does catch is real: a miscompiled backend, a feature combination that
  silently changes a value, a corrupted install, and an implementer's
  transcription error — the values are printed in full, not only compared
  internally.

  Four tests. Two matter: that the derived constants equal what
  `fixtures/vectors.json` records — otherwise the command would confidently
  send strangers after numbers the signed vectors do not contain — and that the
  derivation is **independent of the profile it checks**, since a `verify` that
  reads `UC1::beat()` twice and compares it with itself would report `agrees
  true` on exactly the corrupted build it exists to catch. Verified strict by
  corrupting `UC1::beat()` by one tick behind a feature flag: `agrees` goes
  false and the published-constants test fails.

  Twenty-five new `ucal-json/1` paths, all additions.

- **Four more bodies (A3)** — `luna`, `mercury`, `venus`, `jupiter`, each with
  cited parameters and a derived calendar. `cal list` now shows **seven** derived
  calendars, of which **two** have anchors.

  That ratio is the point. The mechanism is body-independent and shipped four
  bodies, three of them anchored or Saturn — which made a project whose central
  argument is anti-Earth-centric look Earth-centric in its own output. **A body
  without an anchor is the ordinary case**; Earth and Mars are the exceptions,
  because they have had landers and centuries of meridian argument and the
  others have not. That is a fact about where the instruments are, not about the
  mechanism (Rule K.5, Rule Y). A table where the exceptions outnumber the rule
  misrepresents which is which; now it does not.

  **No anchor was invented so that a calendar renders**, and there is a test
  asserting the anchored set is exactly `earth-d, mars-d` — so adding one is a
  deliberate edit rather than something that slips in.

  Two of the new calendars show the mechanism doing what Earth would never ask:

  - **`mercury-d` has fewer than one day per year.** The 3:2 spin–orbit
    resonance makes the solar day about twice the orbit, so the derived
    intercalation is `1/2`. Rule K handles a ratio below one with no special
    case, which is the sort of claim that is worth a test rather than a
    sentence.
  - **`jupiter-d` is a calendar for a body with no surface.** System III
    rotation is a magnetic field, not ground. The mechanism takes periods and
    returns a rule and has no opinion about what is rotating — recorded because
    it is deliberate rather than an oversight.

  **`luna-d` is a free check on Titan's derivation.** Titan's solar day has to be
  derived because nobody publishes one; the Moon's synodic month *is* published,
  at 29.53 d, so the same formula can be run against a number somebody else
  measured. It agrees to the published precision.

  **One thing the model cannot express, stated rather than dropped.** Venus
  rotates retrograde and the fact sheet prints `-5832.6` hours. `Measured`
  carries an unsigned mantissa, so the value stored is the magnitude and the
  sign lives in a comment. What that costs is bounded and now measured: run the
  synodic formula with the magnitude and the answer is 2980 days, wrong by a
  factor of twenty-five; run it with the sign and it is 116.752 days, which is
  the published 2802.0 h. `venus-d` itself is correct — it is built from the
  published solar day and year, both positive — so what is lost is the
  *explanation*, not the calendar. Giving `Measured` a sign is a breaking change
  to a published type that buys one fact about one body; it is recorded as a
  known limitation rather than spent.

- **`cargo run -p xtask -- check-links`** — asks the network whether the cited
  URLs still reach the cited documents. Seven citations, checked at release time
  by a person.

  **Opt-in, and not in CI.** Every other check in this tree is offline and
  deterministic: the same tree gives the same answer on any machine, forever.
  This one depends on third-party servers, and a check that turns the tree red
  because someone else is having a bad morning trains its reader to ignore it —
  which is worse than not having it. "CI green on every push, with no
  known-failing job" is a 1.0 exit criterion, and the way the last false
  criterion survived a whole release was nobody reading a red job. So this one
  is in the release procedure, run by hand.

  **A `200` is not enough, and that is the whole design.** The citation that
  prompted this answered `200 OK`: it redirects to a general NASA page, which
  serves a perfectly good document that is not the one being cited. So a
  redirect that leaves the host is reported separately as `MOVED` — not always
  wrong (an archive link resolves within `web.archive.org`, and
  `stratigraphy.org/chart` merely gains a slash) but always worth a human
  looking.

  It sends a real user-agent, because a default `curl` UA is refused by some
  publishers and reporting a live document dead is its own kind of wrong. It
  shells out to `curl` rather than adding an HTTP client to the workspace.

  Verified strict by restoring both rotted locators: the unreachable one reports
  `FAIL 400`, and the one that answers `200` reports `MOVED`, with the file and
  line each is cited at.

  **What it cannot check** is whether the page still says what was cited. A URL
  that resolves, on the right host, serving a rewritten document, passes this —
  and is exactly the failure a citation exists to prevent. Said in the module
  and in the procedure rather than left for a green run to imply.

## Changed

- **`ucal cal list` reads its anchorless calendars from the registry.** It
  carried a hard-coded `["titan-d"]`, which would have silently omitted every
  body added since — and four were added in the same cycle. `ucal-body` now
  exposes `calendar::registered()` and `calendar::ids()`, one list that both the
  enumerating caller and the building caller read, so they cannot disagree.

- **Anchorless rows now show their `body` and `leap_rule`.** The row claims the
  calendar is "complete in units, intercalation and cycles"; it was not showing
  the intercalation. A claim with the evidence one field away is the cheapest
  kind to substantiate.

## Fixed

- **Two cited URLs no longer resolved.** Found while sourcing A3's parameters,
  and both predate this cycle:

  `NASA_FACT_SHEET` pointed at `nssdc.gsfc.nasa.gov/planetary/factsheet/`, which
  now 307-redirects to a general NASA page — so the citation behind **every**
  body's rotation, solar day and orbital period led nowhere. `IERS` pointed at
  `www.iers.org`, which returns HTTP 400. Both were checked with a browser
  user-agent before being called dead.

  Each locator now points at an archived copy of the document the parameters
  were actually read from, and each `source` string says the original no longer
  serves it and is available in the Internet Archive. A citation names the thing
  that was read; it should also be reachable.

  Now checked, by `check-links` below.

- **`Value::rendered_text` silently dropped `Bool`.** A public helper with a
  catch-all `_ => {}` arm, so a boolean field extracted through it came back as
  the empty string — found while writing `verify`'s tests, where `agrees true`
  rendered as nothing.

  Booleans now render, and the match is **exhaustive**, so a new `Value` variant
  fails to compile here instead of quietly vanishing from the extraction. The
  one variant still skipped is `Bridge`, and it now says why in place rather
  than by omission: this helper has no `Render` to consult, so the default
  answer — not shown — is the correct one, and rendering it would put an Earth
  unit into a text extraction that never asked for one.

## Carried forward from 0.7.0

- **The contact gate is open**, and it is the only thing between this project and
  a 1.0 it would be honest to ship. C1, C2 and C3 are stated in
  [`CONTACT.md`](../CONTACT.md); the cheapest is thirty minutes in any language.
- **The signing key now travels in an artefact the author cannot edit** — the
  `ucal` and `ucal-core` package tarballs on crates.io, as of 0.7.0. What it
  still lacks is an authority that is not this project: a DNS record under its
  own registrar, a third party signing it, or publication with an editorial
  record. First contact remains trust on first use.
- **Titan has no anchor**, and after 0.7.0's literature search the reason is
  specific: the IAU publishes the rotational elements, nobody publishes a
  mean-solar-time convention, and deriving one needs an ephemeris this project
  does not carry. Falsifiable by a single publication.
- **[`GE-U4-walk.sh`](../Proposals/GE-U4-walk.sh) is built and unrun.** Its kill
  criterion needs two readers who have not read this repository.
- **Eight commits in the history are unsigned**, permanently.
