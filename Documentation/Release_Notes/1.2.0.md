# 1.2.0 — UNRELEASED

In development on the `1.2.0` branch. `main` carries the released 1.1.0 line.

## The goal of this cycle: the questions a stranger asks first

1.1.0 made the program easy to *obtain* and easy to *complete a command in*.
This one is about the minute after that: someone has `ucal` in front of them,
has run `ucal datum`, and now wants to know what any of it is for.

That is a different problem from documentation, and the documentation is not
short of words. `CLI.md` is a reference: it answers *what does this field mean*
for a reader who already knows which command to run. Nothing answers **what
should I type first**, and nothing in the program itself makes the case for its
own existence — the book does that, and it is ninety pages away.

### Why this and not something else

Three cycles were spent asking strangers to look
([`CONTACT.md`](../CONTACT.md)) and none came. The asks are still open, and the
remaining work on the author's side of that problem is no longer *removing
obstacles* — 1.1.0 removed the last cheap ones — but **shortening the distance
between running the thing and understanding why it exists**.

This is a guess about a reader who has never existed, which is the same guess
every UI decision here has been. It is stated as a guess.

### Scope

**T1 — `ucal tour`.** A guided first five minutes, printed by the program: a
handful of commands with their output and one sentence each about why the output
looks like that. Not a tutorial and not the book — the shortest path from
"installed" to "I see what this is". It renders as a `Doc` like everything else,
so `--json` gets it too.

**T2 — worked examples in the manual.** `CLI.md` documents 28 items and shows
almost no complete invocations. Each command gets one real example with its
actual output, generated by running it rather than transcribed, so the manual
cannot drift from the program the way two documents already have this year.

**T3 — `ucal explain --why`.** The output of `explain` is dense and every field
is defensible; none of them says *why* it is there. An opt-in flag that annotates
each with the rule or section that requires it — turning the densest output in
the program into its own explanation.

**T4 — an error-message pass.** Every diagnostic is an Appendix E code and a
sentence, and the sentences were written for a reader who knows the
specification. A stranger who types a bad date should be told what a good one
looks like. Measured against the hostile-input corpus, which already enumerates
every rejection the program can produce.

### Done when

A reader who has never seen this project can go from `cargo install ucal` to
running something they chose themselves without opening a browser — and the path
they took is one the program showed them.

That cannot be verified from inside the repository, which is the same problem
this project has had since 0.7.0. What *can* be checked is that every example in
the manual is generated from a real run, and that every diagnostic names a
remedy.

### Explicitly not in scope

- **Anything breaking.** `cargo semver-checks` runs against the published 1.1.0
  and a failure means the release is not a minor one.
- **The two limitations 1.0 froze** — mutually exclusive backends, and the
  library-versus-binary panic asymmetry. Both need 2.0.
- **Rewriting the book into the program.** The book is the argument at length;
  `tour` is the thirty-second version, and if it starts growing chapters it has
  become the wrong thing.

## Carried forward from 1.1.0

- **The contact gate is open.** C1, C2 and C3 in [`CONTACT.md`](../CONTACT.md)
  have gone four cycles unanswered. A finding now costs a major version, and is
  still worth having.
- **The backends are mutually exclusive**, so two libraries that each chose one
  cannot appear in a single dependency graph. Frozen by 1.0; 2.0's to fix.
- **The no-panic guarantee covers the binary, not the libraries.** Also 2.0's.
- **The signing key has no authority behind it that is not the author**, and the
  release checksums are not signed. Both say so where they are used.
- **`ucal-help(1)` is the one dangling manual cross-reference**, because `help`
  is clap's built-in and absent from the command tree until clap builds it.
- **Titan and the four bodies added in 0.8.0 have no anchor**, for the reason
  D5's literature search established.
- **`Measured` cannot express a retrograde rotation.** Breaking to fix.
- **[`GE-U4-walk.sh`](../Proposals/GE-U4-walk.sh) is built and unrun.**
- **Eight commits in the history are unsigned**, permanently.
