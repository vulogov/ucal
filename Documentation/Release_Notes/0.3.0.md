In development on the `0.3.0` branch. `main` carries the released 0.2.0 line.

Nothing is published at this version. Entries below accumulate as work lands;
add to them in the same commit as the change, not on release day.

## The goal of this cycle: not yet chosen

0.2.0 had a single stated goal — supersede the RFC — and every scope item
served it. That is the shape a cycle should have, and this file should not
invent one to look decisive. The goal is recorded here once it is decided.

What follows is the candidate list, drawn from what 0.2.0 carried forward and
from what shipping 0.2.0 exposed. It is a menu, not a plan.

### Candidates

**C1 — `[workspace.dependencies]` for the internal crates.** Thirteen version
requirements are thirteen edits per bump, and the failure mode is silent: miss
one and a `0.3.0` facade resolves against a `0.2.x` core. 0.2.0 fixed the
*missing* `version` keys; it did not fix the multiplicity. Small, mechanical,
and the only candidate with no design question in it.

**C2 — A publish procedure that matches the tool.** `cargo publish --workspace`
does not work for this workspace: verifying a dependent against a dependency
that is not yet on the index fails with a cargo internal error
(`no hash listed for ucal-core`). 0.2.0 shipped by publishing the six crates
sequentially, which preserves full verification because each is checked against
the real index. That is now the procedure and it should be written down and
scripted, rather than rediscovered next time under release pressure.

**C3 — Second-order quadrature in `ucal-cosmo`.** The interval extension is
first-order, so halving the width costs twice the panels. A mean-value form
would be O(h²) but needs a *signed* rational interval type, because the
derivative's bound goes negative and `Ratio` is non-negative by construction.
The honest note from 0.2.0 still holds: at the default depth the arithmetic
width is 40× smaller than the parameter width, so this is not the binding
constraint. It is a candidate only if something makes it one.

**C4 — Raise the `z_of_t` bisection ceiling.** Sixty-four halvings of
`[0, 10000]` resolve `z` to ~5e-16 — still tens of seconds of cosmic time — so
a one-tick tolerance returns `UCAL-E0071`. Honest, and untested as a ceiling:
nobody has tried to raise it and found out what breaks.

**C5 — GE-A4, the two-reader test.** The one experiment the author cannot run.
The protocol is written out in
[`GE-A4-reader-test.md`](../LIFE_UNIVERSE_AND_GOD/GE-A4-reader-test.md) and the
book's dual-audience claim is untested until two people who are not the author
run it. This is a candidate for the cycle only in the sense that the cycle can
*ask*; it cannot complete it alone.

### Explicitly not in scope

- **A UC-2 profile.** GE-6's kill criterion fired and D-21 stands. Settled in
  0.2.0, not reopened here.
- **Renumbering specification sections.** 494 citations depend on the current
  numbering, and `check-docs` would catch a break — which is an argument for
  the check, not for the renumbering.
- **Stabilising the API at 1.0.** Nothing has been used by anyone but the
  author. A stability promise made without a user is a promise about a guess.

## Carried forward from 0.2.0

Open items, none of them regressions. Recorded so the cycle starts with them
visible rather than rediscovered.

- **Titan has no anchor** and will not get one by invention. It needs a
  published convention to cite, or it stays structurally complete and unusable
  for dating (GE-3).
- **The conformance vectors are signed; nothing verifies the signature in CI.**
  `verify-vectors` reports the digest and says **UNSIGNED** when no signature
  is present, which is the honest state of a check that proves integrity and
  not provenance.
- **Eight commits in the history are unsigned.** Removing the co-authorship
  trailers from 0.2.0's history required rewriting those commit messages, and
  that drops signatures with no way to restore them without changing the
  hashes again. The three release tags were re-signed and verify; the rewritten
  commits cannot be. Recorded because a reader checking signatures will find
  the gap and deserves to know what made it.
