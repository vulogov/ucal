# 1.1.0 — 2026-08-07

Make it cheap to try.

The first release under the stability promise, and the first in which adding was
the only thing available. Four items, and **two of them found real defects by
being run rather than written** — a schema that rejected the program's own
output, and a manual page whose cross-references led nowhere.

## The goal of this cycle: make it cheap to try

The first cycle under a stability promise, and the first in which *adding* is
the only thing available.

1.0.0 shipped with the contact gate open — nobody outside this repository has
used any of it. That does not change what can be built; it changes what is worth
building. **Every remaining lever on that problem is a barrier between a curious
stranger and a completed task**, and this cycle is the barriers.

### A correction that sets the scope

0.8.0 dropped three additions — shell completions, a generated man page, a
published JSON Schema — and 0.9.0's notes said they "wait for 2.0". **That was
wrong**, and the error is worth naming because it nearly cost a year.

The rule that deferred them was 0.9.0's own *no new commands or crates*, which
existed to keep that one cycle motionless so an empty `Breaking` section would
mean something. It expired with the cycle. Semver puts an **addition** in a
minor release; only a change that *breaks* something waits for a major one. All
three are additive.

So they are not 2.0's problem. They are this release's scope.

### Scope

**M1 — `ucal completions <shell>`.** bash, zsh, fish, PowerShell, elvish, via
`clap_complete`. Generated at run time from the same `clap` definition the CLI
already carries, so it cannot drift from the commands it completes — the
property that matters more than the feature.

**M2 — a man page**, from `clap_mangen`, generated rather than written for the
same reason. Shipped in the release archives beside `CLI.md`.

**M3 — a published JSON Schema for `ucal-json/1`.** `fixtures/json-surface.txt`
already enumerates every field path and the JSON kind it serialises to, and it
is checked on every push. A schema generated *from that baseline* gives a
consumer something to validate against and cannot disagree with the surface it
describes, because it is derived from the file that defines it.

**M4 — the cost of `cosmo`, measured and published.** GE-1 found depth-24
running in hours and the kill criterion fired; no release promises a runtime and
none will. What is missing is a table letting a reader *choose* a depth instead
of discovering its cost. Measurement, not optimisation.

### Done when

**Met.** M1, M2 and M3 have landed, and M4's table in
[`CLI.md`](../CLI.md) was produced by running the thing — depth 22 took thirteen
minutes of wall clock to measure, which is the point of measuring rather than
estimating.

### Explicitly not in scope

- **Anything breaking.** The floor is in force: no public item removed, no
  signature changed, nothing that compiled stops compiling. Where 0.8.0 could
  spend a break and 0.9.0 chose not to, 1.1.0 **may not**. `cargo semver-checks`
  is a CI job and is no longer advisory — under `1.x` it stops skipping its
  lints and starts failing them.
- **The two limitations 1.0 froze.** The mutually exclusive backends and the
  library-versus-binary panic asymmetry both need breaking changes and are 2.0's.
  They are recorded in [`STABILITY.md`](../STABILITY.md), not forgotten.
- **Waiting.** The contact gate stays open and stays a condition on nothing that
  ships. It is now a condition on whether 1.x was a good idea, which is a
  question only time answers.

## Breaking

**None, and for the first time that is a promise rather than a courtesy.**

Checked three ways rather than asserted: no `pub` item removed or renamed in any
published crate; `fixtures/json-surface.txt` unchanged, so no `ucal-json/1` path
moved; and **all six crates report `no semver update required` against the
published 1.0.0** under `cargo semver-checks`, which runs 196 checks each and
is now load-bearing rather than skipping its lints as it did throughout `0.x`.

## Added

- **`ucal completions <shell>` (M1)** — bash, zsh, fish, PowerShell, elvish.

  **Generated, not written.** The script comes out of the same `clap` definition
  the program parses its own arguments with, at the moment the command runs, so
  it cannot offer a command that does not exist or miss one that does. A
  completion file checked into a repository would be a second description of the
  CLI, and several cycles here have gone on removing second descriptions.

  It is the one command whose output is not a `Doc` — a completion script is a
  shell program, with nothing in it to style, group, round or convert — so it
  returns before the rendering machinery and adds no `ucal-json/1` path.

  Its dead match arm returns a diagnostic rather than `unreachable!()`: the
  `no-panic-in-cli` lint refused the first version, which is the lint doing its
  job on the first new command since it was written.

- **`ucal man [command]` (M2)** — the manual page, in roff, seventeen of them.

  Generated from the argument parser like the completions, and for the same
  reason. Every release archive ships them under `man/`, produced **by the
  binary in that archive** rather than copied from here, so a page describes the
  program it travels with.

  **It takes an argument because the top-level page promised something it could
  not keep.** roff convention makes the `SUBCOMMANDS` section cross-reference
  `ucal-now(1)`, `ucal-between(1)` and the rest; with a single page those were
  dangling, and a reader following one got nothing. `ucal man between` is that
  page. A test reads the references out of the page itself and resolves each,
  rather than checking against a list maintained beside it.

  One reference stays dangling and is named rather than filtered: `ucal-help(1)`
  is clap's own built-in, absent from the command tree until clap builds it.

  All eighteen pages pass `mandoc -Tlint` with zero errors.

- **A JSON Schema for `ucal-json/1` (M3)** —
  [`fixtures/ucal-json-1.schema.json`](../../fixtures/ucal-json-1.schema.json),
  draft 2020-12, one `$defs` entry per command. Promise 4 has been a sentence
  since 0.6.0 and a consumer has had nothing to validate against.

  Generated from `fixtures/json-surface.txt` — not a description of the surface
  but the definition of it, regenerated from the real documents and checked on
  every push. `check-docs` fails if the committed schema is stale, so the two
  cannot drift.

  **Running it against real output found the design wrong.** The first version
  marked every baseline field `required`, on the reading that a field which
  never disappears is a field always present. A real validator refuted it in
  seconds: `explain.claim` appears only under `--claim`; a legacy calendar row
  has no `anchor_revision`; an event without a warning has no `warning`.

  The baseline is a **union over documents**, not a per-document contract, and
  promise 4 says a field never changes *name, shape or meaning* — it never said
  a field is always emitted. A schema with `required` would have been stricter
  than the promise and would have rejected this program's own output. Nothing is
  required now, and there is a test asserting nothing ever is.

  Validated by hand against a real JSON Schema implementation across all 21
  commands, with and without `--bridge`: 0 failures. The committed tests check
  the properties rather than re-implementing a validator, and say so.

## Changed

- **`cosmo`'s cost is measured and published (M4).**
  [`CLI.md`](../CLI.md) gains a table of wall time against enclosure width for
  `--depth` 4 through 22, measured on an Apple M5 Pro rather than estimated.
  Depth 24 was not run; on the trend it is about an hour, which is what GE-1
  found when its kill criterion fired.

  **The useful column is not the time.** An enclosure has two widths and only
  one of them answers to `--depth`. The *parameter* width — 11 353 years at
  `z = 1100`, from the published uncertainty on the Planck 2018 constants — does
  not move at any depth, because no amount of subdivision improves somebody
  else's measurement.

  So the arithmetic share falls from 85% of the total at depth 4 to 2.2% at the
  default 12, and 0.14% at 16. Past there each step costs four times as much to
  narrow something already invisible. **The default is not a compromise; it is
  roughly where the two widths stop being comparable.** Deeper is for
  demonstrating that the quadrature converges, which is a different question
  from wanting a better answer.

  No release promises any of these timings, and `STABILITY.md` still says a
  future release may be slower if being slower is more correct. The table exists
  so a depth can be chosen rather than discovered.

## Fixed

- **Enabling both backends reported a duplicate definition before the guard.**
  1.0's newtype needed two `konst` definitions — `const` on the fixed-width
  backend, not on the heap one — and the second was gated on `bigint` rather
  than on `bigint AND NOT u512`. With both features on, both compiled, and
  `the name konst is defined multiple times` arrived ahead of the sentence
  explaining what the caller had actually done wrong.

  This is the defect 0.6.0 fixed for the `imp` module, reintroduced by the last
  release before the surface froze. The `features` workflow caught it on the
  first push of this cycle, which is the workflow doing exactly what it was
  written for — and it is the second time it has caught a defect that reached a
  release, after the false MSRV.

## Carried forward from 1.0.0

- **The contact gate is open.** C1, C2 and C3 in [`CONTACT.md`](../CONTACT.md)
  have gone three cycles unanswered. They are worth more now than before 1.0,
  not less: a finding that arrives today costs a major version rather than a
  minor one, and it is still much better to know.
- **The backends are mutually exclusive**, so two libraries that each chose one
  cannot appear in a single dependency graph. Frozen by 1.0; 2.0's to fix.
- **The no-panic guarantee covers the binary, not the libraries.** Also 2.0's.
- **The signing key has no authority behind it that is not the author.** It
  travels in the crates.io tarballs, which cannot be edited after publication,
  so a change is detectable — but first contact remains trust on first use.
- **Release checksums are not signed**, and the release body says so.
- **Titan and the four bodies added in 0.8.0 have no anchor**, for the reason
  D5's literature search established: the rotational elements are published and
  the solar-time convention is not.
- **`Measured` cannot express a retrograde rotation.** Breaking to fix.
- **[`GE-U4-walk.sh`](../Proposals/GE-U4-walk.sh) is built and unrun.**
- **Eight commits in the history are unsigned**, permanently.
