# 1.1.0 — UNRELEASED

In development on the `1.1.0` branch. `main` carries the released 1.0.0 line.

## The goal of this cycle: make it cheap to try

The first cycle under a stability promise, and the first in which *adding* is
the only thing available.

1.0.0 shipped with the contact gate open — nobody outside this repository has
used any of it. That does not change what can be built; it changes what is worth
building. **Every remaining lever on that problem is a barrier between a curious
stranger and a completed task**, and this cycle is the barriers.

### A correction that sets the scope

0.8.0 dropped three additions — shell completions, a generated man page, a
published JSON Schema — and 0.9.0's notes said they "wait for 2.0". **That was
wrong**, and the error is worth naming because it nearly cost a year.

The rule that deferred them was 0.9.0's own *no new commands or crates*, which
existed to keep that one cycle motionless so an empty `Breaking` section would
mean something. It expired with the cycle. Semver puts an **addition** in a
minor release; only a change that *breaks* something waits for a major one. All
three are additive.

So they are not 2.0's problem. They are this release's scope.

### Scope

**M1 — `ucal completions <shell>`.** bash, zsh, fish, PowerShell, elvish, via
`clap_complete`. Generated at run time from the same `clap` definition the CLI
already carries, so it cannot drift from the commands it completes — the
property that matters more than the feature.

**M2 — a man page**, from `clap_mangen`, generated rather than written for the
same reason. Shipped in the release archives beside `CLI.md`.

**M3 — a published JSON Schema for `ucal-json/1`.** `fixtures/json-surface.txt`
already enumerates every field path and the JSON kind it serialises to, and it
is checked on every push. A schema generated *from that baseline* gives a
consumer something to validate against and cannot disagree with the surface it
describes, because it is derived from the file that defines it.

**M4 — the cost of `cosmo`, measured and published.** GE-1 found depth-24
running in hours and the kill criterion fired; no release promises a runtime and
none will. What is missing is a table letting a reader *choose* a depth instead
of discovering its cost. Measurement, not optimisation.

### Done when

M1–M3 have landed or been recorded as dropped with a reason, and M4 has a table
in `Documentation/CLI.md` that was produced by running the thing rather than by
estimating it.

### Explicitly not in scope

- **Anything breaking.** The floor is in force: no public item removed, no
  signature changed, nothing that compiled stops compiling. Where 0.8.0 could
  spend a break and 0.9.0 chose not to, 1.1.0 **may not**. `cargo semver-checks`
  is a CI job and is no longer advisory — under `1.x` it stops skipping its
  lints and starts failing them.
- **The two limitations 1.0 froze.** The mutually exclusive backends and the
  library-versus-binary panic asymmetry both need breaking changes and are 2.0's.
  They are recorded in [`STABILITY.md`](../STABILITY.md), not forgotten.
- **Waiting.** The contact gate stays open and stays a condition on nothing that
  ships. It is now a condition on whether 1.x was a good idea, which is a
  question only time answers.

## Fixed

- **Enabling both backends reported a duplicate definition before the guard.**
  1.0's newtype needed two `konst` definitions — `const` on the fixed-width
  backend, not on the heap one — and the second was gated on `bigint` rather
  than on `bigint AND NOT u512`. With both features on, both compiled, and
  `the name konst is defined multiple times` arrived ahead of the sentence
  explaining what the caller had actually done wrong.

  This is the defect 0.6.0 fixed for the `imp` module, reintroduced by the last
  release before the surface froze. The `features` workflow caught it on the
  first push of this cycle, which is the workflow doing exactly what it was
  written for — and it is the second time it has caught a defect that reached a
  release, after the false MSRV.

## Carried forward from 1.0.0

- **The contact gate is open.** C1, C2 and C3 in [`CONTACT.md`](../CONTACT.md)
  have gone three cycles unanswered. They are worth more now than before 1.0,
  not less: a finding that arrives today costs a major version rather than a
  minor one, and it is still much better to know.
- **The backends are mutually exclusive**, so two libraries that each chose one
  cannot appear in a single dependency graph. Frozen by 1.0; 2.0's to fix.
- **The no-panic guarantee covers the binary, not the libraries.** Also 2.0's.
- **The signing key has no authority behind it that is not the author.** It
  travels in the crates.io tarballs, which cannot be edited after publication,
  so a change is detectable — but first contact remains trust on first use.
- **Release checksums are not signed**, and the release body says so.
- **Titan and the four bodies added in 0.8.0 have no anchor**, for the reason
  D5's literature search established: the rotational elements are published and
  the solar-time convention is not.
- **`Measured` cannot express a retrograde rotation.** Breaking to fix.
- **[`GE-U4-walk.sh`](../Proposals/GE-U4-walk.sh) is built and unrun.**
- **Eight commits in the history are unsigned**, permanently.
