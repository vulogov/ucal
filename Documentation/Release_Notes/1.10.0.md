# 1.10.0 — UNRELEASED

In development on the `1.10.0` branch. `main` carries the released 1.9.0 line.

## The goal of this cycle: a requirement with no wire

This project has found the same shape in its own work four times now, and given
it a name each time.

- **A claim with no mechanism** — 1.5.0, and the rule that every claim in the
  documentation must be checkable by something that runs.
- **A mechanism with no wire** — 1.6.0's audit, which found fourteen checks that
  could report success having examined nothing.
- **A schedule with no date** — 1.8.0, where `ROAD-TO-2.0`'s *"whenever the work
  is done"* read like a plan and functioned as a deferral for five cycles.
- **A procedure whose steps undo each other** — 1.8.0 again: the documented
  verification block rebuilt the binary without `tui` and then ran it.

[`H1`](../Proposals/H1-when-does-a-calendar-hold.md) found the fifth, and it is
the first one where the specification uses the word **MUST**.

`crates/ucal-body/src/param.rs` opens by quoting the rule it implements:

> MUST warn (`UCAL-W0003`) and MUST NOT silently extrapolate.

`RatedParam::evaluate` does warn. It has one production caller, and that caller
binds the warning to `_` on the line that produces it. `ucal cal show earth-d` at
fifty thousand years — five times outside Earth's declared validity window —
returns a date and exits 0. `W0003` occurs zero times in any output this program
can emit.

**And it is worse than one dropped value.** `Body::days_per_year(at)` exists
precisely to combine both parameters' warnings, and its doc comment says why:

> so an evaluation outside a validity window cannot become invisible by being
> combined with another (Rule C, `UCAL-W0003`).

It has five call sites and every one is a test. `BodyCalendar::build` calls
neither, reading `value_at_epoch()` directly. Three layers of correct machinery,
and the production path goes round all of them.

The question a reader asked to surface it was simpler than any of that:
**satellites appear and disintegrate, orbital parameters change — so how can we
specify a cycle, but *when*?** Every part of the answer already exists in this
tree. None of it is connected to anything a user can see.

### Scope

**M1 — connect the warning.** `DerivedFields` already propagates uncertainty by
interval arithmetic; it gains a warning, and every command that renders local
fields renders it. `BodyCalendar` stops going round `days_per_year`.

The work is not the warning — it is that `Doc` has no warning channel, so
`cal show`, `show`, `cal derive --at` and the wall clock's dials all need one.

**Stop if** surfacing it makes the common case noisy. It should not: every
shipped calendar's window is ±10 000 Julian years. If that turns out to be
wrong, the finding is that the declared windows are too narrow for the dates
people actually ask about, which is worth knowing and is a different repair.

**M2 — one convention for when a parameter is read.** Today the solar day is
evaluated at the instant while the leap rule and the cycle are frozen at the
epoch. No shipped parameter declares a rate, so this produces **no numeric
difference at all** today — it is structural, and it would become real the moment
a rate is added.

H1 recommends freezing all three and saying so, because a counting convention
whose rule changes underneath the count is not one. Drift belongs in M1's
warning, not in a silently varying year length.

**Stop if** freezing breaks `earth-civil`'s agreement with `hifitime` over its
checked range. It should not — freezing is what the code already does for two of
the three quantities.

**M3 — seasons, or the recorded reason there are none.** Obliquity is declared
for ten bodies and read by nothing but two tests. A seasonal subdivision needs no
satellite, so it exists for the fourteen calendars that have no cycle at all —
which is what the reader was reaching for when they asked whether a "universe
month" could be tied to orbital parameters.

**The obstacle is stated before anyone starts.** `AngleParam` holds one number,
the obliquity in degrees. That gives a season's *amplitude* and not its *phase*:
placing an equinox needs the orientation of the spin axis, which the cited IAU
WGCCRE report publishes and this project stores nowhere. And a phase is Rule J.3
empirical — determined and cited, never derived.

**Stop if** the pole orientation cannot be quoted verbatim for the bodies that
have an obliquity. Then obliquity stays carried and unused, with that as the
recorded reason — which is better than the present state, where it is carried and
unused with no reason recorded anywhere but a doc comment.

### Done when

A parameter evaluated outside its validity window says so, wherever it is read —
or the release notes say which path still swallows it and why.

**M1 is the one that would be hard to justify carrying.** The spec says MUST, the
code produces the warning correctly, and one underscore keeps it from everybody.

## Fixed

- **`1.10.0` sorted before `1.9.0`, and a check quietly read the wrong file.**
  Found on this cycle's *first commit*, by the defect corpus, before any of the
  cycle's actual work began.

  `check_ci_covers_the_procedure` reads "the newest release-notes file" to
  compare the documented verification block against what CI runs. It picked that
  file by sorting filenames **lexicographically**, which puts `1.10.0.md`
  between `1.1.0.md` and `1.2.0.md` — so the newest was `1.9.0.md`, and the
  check began reading the *previous* release's procedure while reporting
  success.

  **Latent since 1.0.0 and unreachable until now**: this is the first version
  where lexicographic and numeric order disagree. The corpus mutation edits the
  current cycle's notes, so a check reading the last cycle's notes cannot see it,
  and it came back `SURV` — the first survivor since 1.7.0 built the corpus.

  **The fix is not a better sort.** Sorting numerically repairs that one bug and
  leaves the guess in place. The check now reads the notes for **the version
  being built**, derived from `[workspace.package]` — no ordering, nothing to
  get wrong.

  That also closes an adjacent failure the sort could not: a version bumped and
  its notes never written. Under the sort that silently read the previous
  cycle's file and passed; it is now an error naming the version.

  Two tests, and the first draft of the second one was not strict. It asserted
  that *some* error came back and that the message named the version — which
  passed with the check disabled, because `read_to_string` fails too and its
  message contains the path, and the path contains the version. A test that
  cannot tell the two branches apart is not testing the branch it claims to.

  It is worth naming what caught it. The corpus exists because *"a check nobody
  has seen reject anything is a check nobody has seen work"*, and this is the
  first time it has caught a defect that no amount of reading would have found —
  the code was correct for every version number that had ever existed.

  A sweep for the same class found no other version-ordering assumption in the
  tree: everything else treats a version as an opaque string. It did find one
  thing, in the fix itself — the new function's doc comment had swallowed
  `check_ci_covers_the_procedure`'s, leaving that function undocumented. **The
  third time in this project that inserting an item above another has stolen its
  doc comment**, after `data::all` in 1.9.0's F9 and `cmd_cal_validate` in F4.

## Carried forward from 1.9.0

- **1.9.0 is the first release whose binaries a downloader can check end to end**
  — published crates against the tag, binaries against their checksums, and that
  file against a signature made by hand. Every release before it is unsigned and
  will not be signed retrospectively: signing a 2026 checksum file today would
  say a key vouched for it today, which is not the claim a reader would take.
- **The signing key has no authority behind it that is not the author.** C1
  closed the half of that sentence which was about this repository. This half is
  about the world, and no mechanism reaches it.
- **`cargo package` is byte-reproducible**, measured across two releases now.
  C3's planned fallback has never fired and stays for a future cargo that stops
  normalising mtimes.
- **`-D warnings` reaches the default build and not the twenty-three reduced
  ones**, which carry three unused-import warnings. The same shape as 1.9.0's G2:
  a standard applied in one place and not the one beside it.
- **`ucal now` renders eleven rungs below what any clock can fill**, and now says
  so rather than calling it `precision`. The bottom nine rungs of the ladder are
  below anything any instrument can observe — the shortest interval ever measured
  is ~10⁻¹⁹ s, between `T-5` and `T-6`.
- **§15.1 is `UNIMPLEMENTED`** for `ucal-body` (D-A20), and **an arena for the
  library's loader** is still the path nobody has costed.
- **`cargo semver-checks` has one known blind spot**, covered by four
  compile-pass fixtures. Six further categories were probed in A3.
- **Three single-site conditions still share codes with other meanings** (D-A24).
- **A rounded parameter is a different calendar** — measured in 1.9.0, and the
  answer is that fifteen calendars rest on nineteen distinct published figures of
  which fourteen decide a leap rule outright.
- **Fourteen of the fifteen calendars have no cycle**, because they declare no
  grouping satellite. §15.3 forbids a fallback, so that is the answer.
- **The three asks in [`CONTACT.md`](../CONTACT.md)** are open, wanted, and a
  condition on nothing shipping.
- **[`GE-U4-walk.sh`](../Proposals/GE-U4-walk.sh) is built, run, and waiting on
  two readers.**
- **Eight commits in the history are unsigned**, permanently.
