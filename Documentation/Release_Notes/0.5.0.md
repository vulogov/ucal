# 0.5.0 — 2026-08-05

No rule is enforced by convention alone, and the conformance vectors are signed.

**The first release since 0.2.0 with no breaking change** — checked against
`v0.4.0` rather than assumed, since assuming it is what the previous two
releases got wrong.

## The goal of this cycle: no rule enforced by convention alone

[`ROAD-TO-1.0.md`](../Proposals/ROAD-TO-1.0.md) found the correlation this cycle
acts on. Of twenty-four rules, **two were enforced by convention alone** — F and
R — and **every alignment defect a reader found across 0.3.0 and 0.4.0 landed on
Rule R.** No type-enforced rule leaked once.

That is not a failure of the idea. It is §29's argument arriving from the
inside: review is not enough, and the rule left to review is the one that failed.

## Added

- **`rounding-is-declared` lint.** Every `to_decimal_string` or `snap` in a
  shipped *library* crate must carry a marker saying why its mode and digit
  count are fixed rather than the caller's. `crates/ucal` is exempt by
  construction: `Value::quantity` is the only render path there and a property
  test already fails if a call site bypasses it.

  Four sites needed a marker, and each has a reason rather than a shrug:

  | site | why the mode is forced |
  |---|---|
  | `calendar.rs` day fraction | `Trunc` is **required** — a fraction rounded up reaches `1.0000` and names the following day, so half-even would make `render` disagree with `fields`. The four digits are the label's grammar (§6.6), like the two digits of a civil minute. |
  | quadrature lower sum | the *lower* sum, so it truncates down; direction forced by which bound it builds |
  | quadrature upper sum | the *upper* sum, so it ceils up |
  | audit prose figures | truncated so no number in a description of outward rounding is itself rounded up — and the audit now says so in its first line |

- **`the_quadrature_snaps_outward`.** The markers above claim a direction; this
  checks it. Snapping the lower sum can only lower it and the upper sum can only
  raise it, so the enclosure cannot tighten. A transposed pair would still
  produce a plausible interval — narrower than the truth, and wrong.

- **`the_audit_declares_its_own_rounding`**, and an opening step in the audit
  that states its figures are truncated to twelve digits.

- **The conformance vectors are signed.** Carried since 0.2.0.
  `xtask -- verify-vectors` reports the signature instead of `UNSIGNED`, and the
  trusted comment carries the digest — signed along with the file, so a
  signature cannot later be presented as vouching for a different one.

  `spec/CONFORMANCE.md` now states the **custody**, and that is the part worth
  having. One key, one maintainer, one machine, an offline backup; no rotation
  procedure, no revocation path, no timestamping authority. A verifier learns
  that the holder of `D0E4E5A9439E54CC` vouched for this digest, and does not
  learn that the key is still under its holder's control — nor can they learn it
  from anything in this repository.

  The failure mode of signing is not a forged signature. It is a reader seeing
  one and inferring a release process that does not exist.

- **`profile_without_a_frame.rs`** — a compile-fail case proving that a profile
  declaring no frame does not compile. `Profile::FRAME` is a required associated
  constant with no default; that was true before this cycle and nothing said so.

- **`every_command_that_reports_a_profile_names_its_frame`.** `datum`'s frame
  was checked; `doctor`'s was not. A frame declared and never shown has been
  stated to nobody.

- **`every_lint_is_listed_for_suppression_reporting`.** A lint absent from
  `LINT_NAMES` can be suppressed without the report mentioning it — an exemption
  that is not a visible cost, which is the one thing the marker machinery exists
  to prevent. Three lints added in 0.3.0 and 0.4.0 were missing from that list,
  so the four exemptions this cycle needed went unreported until the test was
  written. Ten exemptions are now listed on every run.

## Changed

- **Rule R's enforcement line, in `spec/RULES.md`.** It read *convention plus
  review*; it now names the type system, the lint and the tests that 0.4.0 and
  this cycle built. The entry also records the history, because the enforcement
  line is what a reader consults to know what is guaranteed — and being told a
  guarantee is weaker than it is misleads as surely as the reverse.

  Rules enforced by convention alone: **F only**, down from F and R.

- **Rule F's enforcement line, in `spec/RULES.md`.** It read *convention*, and
  that understated it in the reader's disfavour — the opposite of Rule R's
  problem and the same defect. `Profile::FRAME` is a required constant, so a
  frameless profile does not compile; and every value is `Instant<P>`, so values
  declared in different frames are different types and cannot be combined. Both
  were always true. Neither was written down, and neither was checked.

  What stays convention is now stated as the whole of it, and it is
  irreducible: **that the frame declared is the frame the numbers were computed
  in.** No type can check that, and the rule does not ask for it — Rule F
  requires the frame to be *stated*, not to be true. The guarantee is that the
  claim is on the record, so being wrong about it is visible rather than
  assumed.

  **Rules enforced by convention alone: none.** That was this cycle's goal.

## Fixed

- **The `rounding-is-declared` lint's crate detection matched the repository.**
  It identified the CLI crate by searching the path for a component named
  `ucal` — and the repository directory is called `ucal` too, so every absolute
  path matched and the check silently passed the entire tree. It now takes the
  first component *relative to* `crates/`.

  Found by making the lint print what it was deciding, after it reported a clean
  run on a tree that visibly was not.

## Internal

- Workspace and all seven packages at `0.5.0`. One edit to one file, which is
  what C1 was for: `cargo tree` confirms all twelve internal edges resolve to
  the local `0.5.0`, and `version-lockstep` confirms the six requirements moved
  together.

- The lint excludes `#[cfg(test)]` code, since a test asserting that `1/3`
  renders as `0.33333` is not a shipped rendering — there are forty of them. The
  exclusion is a convention rather than a parse, so it **checks its own
  assumption**: if anything after the marker looks like shipped code, the extent
  becomes the whole file and the violations reappear. Over-excluding is the
  dangerous direction, and this is what stops it being silent.
