# 1.3.0 — UNRELEASED

In development on the `1.3.0` branch. `main` carries the released 1.2.0 line.

## The goal of this cycle: find the defects nobody is going to report

Five cycles of asking have produced no users, so **the only source of findings
is the machine**. That is not a complaint; it is a fact that ought to change
what gets built, and this cycle is the first to be chosen on it rather than
around it.

The evidence is in the last three release notes. Every defect found since 0.7.0
was found by *running something*: a workflow that had never passed, a schema
that rejected the program's own output, a tour step whose row vanished, twelve
diagnostics that named no remedy, four error codes borrowed from conditions that
had not happened. None came from a person. All of them came from a check that
had not existed the week before.

So build more checks — of the kind that find what a person would have.

### What this cycle admits about itself

The obvious objection is that this is the project marking its own homework, and
it is. A fuzzer finds crashes and disagreements; it cannot tell you the design
is wrong, that `--bridge` should have been the default, or that nobody wants a
Mercurian calendar. Those need a reader, and the asks in
[`CONTACT.md`](../CONTACT.md) are still open and still unanswered.

What machine checks *can* do is make sure that when someone finally looks, what
they find is a disagreement about design rather than a crash on a malformed
date. That is worth a cycle.

### Scope

**F1 — a real fuzzer, not a corpus.** `hostile_input.rs` is forty hand-chosen
invocations and its own module says it is not a fuzzer. `cargo-fuzz` over the
parsers — instants, tiers, civil dates, redshifts, forms — with the property
being the one already promised: **no panic, and a diagnosed rejection or a
value, never anything else.** Findings become corpus entries, so a crash found
once is checked forever.

**F2 — round-trip properties.** Every text form parses back to the value it was
rendered from; every UCID round-trips; every canonical byte encoding round-trips;
`between` reassembles. Some of this exists as examples and none of it as a
property over generated input.

**F3 — a differential check against the second backend, over generated input.**
Rule W says `u512` and `bigint` accept and reject exactly the same values, and
it is verified today by running the same *test suite* twice. That is not the
same claim: it shows the two agree on inputs somebody thought of.

**F4 — the arithmetic invariants, as properties.** Rule O forbids wrapping;
Rule Z forbids results before the datum; Rule T says a coarser statement denotes
an interval that contains the exact value. Each is a property over arbitrary
instants and tiers, not a handful of cases.

### Done when

A fuzzer has run long enough to be boring, its corpus is committed, and the
properties above hold over generated input on both backends — with every finding
either fixed or recorded with a reason.

**And the honest condition:** if the fuzzer finds nothing, that is reported as
nothing found. A clean fuzz run is weak evidence presented as strong more often
than almost anything else in software, and the notes will say how long it ran
and against what.

### Explicitly not in scope

- **Anything breaking.** `cargo semver-checks` runs against the published 1.2.0.
  A fuzz finding that needs a breaking change to fix is recorded for 2.0, not
  smuggled in.
- **The three 2.0 items** — mutually exclusive backends, the library-versus-
  binary panic asymmetry, and `Measured` having no sign.
- **Pretending this substitutes for contact.** It does not, and the section
  above says so rather than letting a green fuzz run imply it.

## Added

- **[`fuzz/`](../../fuzz/README.md) (F1)** — three `cargo-fuzz` targets over the
  widest input surfaces: the CLI's instant parser, the §6 codec in both forms,
  and Rule B's 64-byte wire format.

  Two of them assert more than "does not crash". `parse_forms` re-renders and
  re-parses whatever parsed, so it is hunting a string that parses to one value
  whose rendering parses to another — a round-trip break, which no crash would
  reveal. `decode_bytes` requires that whatever decodes re-encodes to the bytes
  it came from, which is what makes Rule B's encoding canonical rather than
  merely accepted.

  Outside the workspace (`exclude = ["fuzz"]`), because it needs nightly and
  libFuzzer and the MSRV job pins 1.87. Not in CI: a fuzz job either has a time
  budget, and proves less every time the code grows, or has none and is not a CI
  job.

  **Seeds are committed; the generated corpus is not; crash artefacts are.** The
  corpus reaches fifteen hundred files and six megabytes in minutes and is a
  cache that fuzzing rebuilds. A crash artefact is the opposite — an input that
  broke something once must be checked on every run after — so `artifacts/` is
  tracked, and is currently empty.

- **`crates/ucal-core/tests/properties.rs` (F2, F3, F4)** — the invariants over
  ten thousand generated inputs instead of over a list of cases.

  **F2, round trips.** Every text form parses back to the value it was rendered
  from, at tick precision; every UCID round-trips; every canonical encoding
  round-trips. The generator builds instants from up to eight 64-bit words, so
  the high tiers are actually reached — one that produced `u64`-sized values
  would test 64 bits of a 512-bit domain and report that everything was fine.

  **F4, the rules.** Rule Z: the larger minus the smaller is always a value, the
  smaller minus the larger is always an error rather than a wrap, and the
  difference reconstructs. Rule T: the window a coarser statement denotes always
  contains the instant it came from, flooring is idempotent, and ceiling never
  falls below flooring. Rule O: the ceiling refuses rather than wraps, and one
  tick below it is exactly reachable.

  **F3, Rule W, and why it is a digest.** Rule W says both backends accept and
  reject exactly the same values, and it was verified by running the same suite
  twice — which shows only that they agree on inputs somebody thought of. The
  backends are mutually exclusive so no process can compare them directly, so
  every generated result is folded into one number and compared with a committed
  constant that **both backends must reach**. They do. Verified load-bearing by
  perturbing one operation: the digest changes and the test fails.

  **No property-testing crate, and no random seed.** A suite that passes today
  and fails tomorrow on the same tree would destroy "CI green on every push with
  no known-failing job", which is a stated criterion. The generator is a
  deterministic xorshift over a fixed seed; widening the search is a visible
  edit to `ROUNDS` rather than a lucky run. What that costs is shrinking, and
  the module says so.

## Verification

```
cargo test --workspace --release
cargo test --workspace --exclude xtask --release --no-default-features \
  --features bigint,std,ucal-civil/hifitime,ucal/civil,ucal/body,ucal/events,ucal/cosmo
RUSTFLAGS="-D warnings" cargo build --workspace --all-targets --release
cargo build -p ucal-core --target wasm32-unknown-unknown \
  --no-default-features --features u512
cargo run -p xtask && cargo run -p xtask -- lint \
  && cargo run -p xtask -- check-docs && cargo run -p xtask -- verify-vectors
```

With F1–F4 landed: 534 tests on the default backend, 491 on bigint, both
reaching the same Rule W digest over ten thousand generated inputs.

**What the fuzzer found: nothing.** Recorded as nothing found, with the numbers,
because a clean fuzz run is weak evidence presented as strong more often than
almost anything else in software:

| target | executions | found |
|---|---|---|
| `parse_instant` | 37.6M in 121 s, then 214.2M in 601 s | nothing |
| `parse_forms` | 12.8M in 121 s | nothing |
| `decode_bytes` | 162.6M in 121 s | nothing |

One machine, three entry points, minutes rather than days. It says the parsers
do not crash on adversarial bytes. It says nothing about whether the values they
produce are the right ones — that is what the properties above and the
conformance vectors are for.

At the opening: 528 tests on the default backend, 485 on bigint, `-D warnings`
clean across all targets, wasm `no_std` green, the UC-P0 constants harness
meeting its exit criterion on both routes, lints clean, nine `check-docs` checks
passing, 118 citations resolving, all eighteen standing spec deltas applied to
the normative text, nine cited URLs reaching their documents, MSRV 1.87
verified, fifteen feature combinations building, all six crates clean under
`cargo semver-checks` against the published 1.2.0, and the conformance vectors
re-deriving to a signed digest.
